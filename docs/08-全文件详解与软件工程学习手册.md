## 0. 项目全景：这个项目是什么、怎么分层

ZA量化 = 连接天勤行情服务 → 把行情变成统一格式 → 算技术指标和决策评分 → 通过 HTTP/WebSocket 提供给网页 → 网页画出专业 K 线 → 还能打包成桌面软件。

```
┌────────────────────────────────────────────────────────────┐
│ ⑤ 前端 static/        你看得见的部分（HTML/CSS/JS + ECharts）  │
├────────────────────────────────────────────────────────────┤
│ ④ 接口层 api/         FastAPI：HTTP 查询 + WebSocket 推送     │
├────────────────────────────────────────────────────────────┤
│ ③ 业务层 market/      指标计算 + 决策评估引擎（纯函数，最好学）  │
├────────────────────────────────────────────────────────────┤
│ ② 数据层 两条路线（对比学习的主角）                             │
│    C:  tqdiff/     自己实现天勤 DIFF 协议（asyncio + WebSocket）│
│    AB: tq/         封装 TqSdk（线程 + 命令队列 + 协程）          │
├────────────────────────────────────────────────────────────┤
│ ① 入口/配置  main.py launcher.py config.py                     │
└────────────────────────────────────────────────────────────┘
        + 桌面壳 electron/ · 打包 PyInstaller · 测试 tests/ · 文档 docs/
```

**最重要的软件工程思想**：分层 + 依赖单向。上层只认识下层的"接口"，不认识实现。
所以数据层有 A+B 和 C 两套实现，上面几层几乎不用改——这就是"可替换性"的价值。

## 1. 入口与配置层

### 1.1 `main.py`（37 行，开发入口）

- **功能**：`python main.py` 启动整个后端。
- **技术点**：
  - `faulthandler.dump_traceback_later(30, repeat=True)`：每 30 秒把所有线程的调用栈转储到 stderr——**死锁诊断神器**（本项目真用过）；
  - 组合式启动：`load_config()` → `create_app()` → `uvicorn.run()`，每步只做一件事。
- **学到**：入口文件应该薄，只做"装配"，不写业务。

### 1.2 `launcher.py`（打包版入口）

- **功能**：exe 双击后的入口；首次运行生成配置、启动服务、自动开浏览器。
- **技术点**：
  - `sys._MEIPASS`：PyInstaller 把资源解压到临时目录，这个变量告诉你资源在哪（**打包资源路径**经典问题）；
  - `threading.Thread(target=open_browser, daemon=True)`：后台线程延迟 1.2 秒开浏览器，`daemon=True` 表示主进程退出它自动死；
  - 优雅降级：读不到 VERSION 就给默认值。
- **学到**：桌面软件的"首次运行体验"（first-run experience）怎么做。

### 1.3 `config.py`（配置 + 凭据存储，147 行）

- **功能**：加载服务配置和天勤账户凭据；提供本地凭据存储（登录界面的"cookie"）。
- **技术点**：
  - `@dataclass`：用类优雅地承载配置（自动生成 `__init__`，带类型标注）；
  - **配置分层优先级**：环境变量 > 本地凭据存储 > config.json——为什么？（密码不进文件/仓库，运行环境可覆盖）；
  - 凭据存储 = 一个 JSON 文件读写（`save_credentials`/`load_saved_credentials`），放在 git 忽略的 `.tqsdk/` 目录——"像 cookie 一样"；
  - 防御式解析：所有 `float()/int()` 都可能抛异常，逐项 try。
- **学到**：配置管理三原则（分层覆盖、密钥与代码分离、失败给中文可读错误）。

### 1.4 `config.json` / `config.json.example` / `VERSION`

- **功能**：运行配置模板 + 版本号。
- **技术点**：`.gitignore` 排除真实配置、保留 example 模板——**密钥卫生**（secrets hygiene）；`VERSION` 单一事实来源，打包时嵌进 exe，启动时读出来显示。
- **学到**：为什么"密码永远不该出现在 git 里"（本项目全历史搜索密码 0 次命中，这是标准答案）。

## 2. 数据层（两条路线，本项目最有学习价值的部分）

> 同一个"接口"（`subscribe/get_kline/get_instrument/query_instruments`），两套实现。
> 这是**适配器模式 + 防腐层（Anti-Corruption Layer）**的活教材。

### 2.1 AB 路线：`tq/client.py`（≈600 行，难度 ★★★★）

- **功能**：封装 TqSdk——连接、订阅、合约查询、K 线拉取。
- **核心难题与解法**（每一行都是课）：
  - **TqSdk 不是线程安全的** → 只允许一个线程碰它。其他线程（HTTP 请求）怎么办？
    → **命令队列模式**：把请求打包成 `_Cmd(command, args, future)` 扔进 `queue.Queue`，
    事件循环线程逐个执行并把结果塞回 `Future`。这就是"生产者-消费者 + Future"模式；
  - **命令超时**：等待方 30 秒等不到就放弃，但命令还在队列里会白执行 →
    `abandoned` 标记，执行前跳过（**取消语义**，防止活锁）；
  - **登录失败不能死**：`_run` 里对首次连接失败做 5 秒重试循环（**fail-safe 重试**）；
  - **连续超时**：3 次 → 判定连接坏了 → 强制重连（**自愈**）；
  - **K 线缓存**：`_kline_cache[(symbol, period)] = (时间戳, 数据)`，5 秒 TTL——**缓存击穿的朴素解法**；
  - **坏 serial 清理**：tqsdk 内部注册表被污染时手动删除重试（跟第三方库内部状态打交道的代价）；
  - **目录后台协程**：`api.create_task()` + `await`——TqSdk 官方协程模式，让慢查询分批让出事件循环。
- **学到**：线程模型、命令队列、Future、超时/取消/重试/自愈、第三方库封装的完整心法。

### 2.2 AB 路线：`tq/instruments.py`（合约目录管理）

- **功能**：866 个期货合约的"黄页"：按交易所/关键词查、单个查、进度查询。
- **技术点**：
  - **钩子模式**：`set_catalog_hooks(needs_futures, on_futures, next_batch, on_result)`——
    管理器只提供数据，协程只负责调度，两者解耦（**关注点分离**）；
  - **失败冷却**：`_failed_cache[symbol] = 时间戳`，30 秒内不重试——防止雪崩式重试；
  - **大小写规范**：`EXCHANGE_INSTRUMENT_CASE` 表驱动（SHFE 小写、CZCE 大写……）——**表驱动编程**；
  - `normalize_symbol`：裸代码（如 `rb2610`）逐交易所探测——**试探式归一化**。
- **学到**：进度式数据加载、幂等、表驱动、失败冷却。

### 2.3 AB 路线：`tq/subscriber.py`（订阅管理）

- **功能**：订阅/退订的统一入口，返回 `{subscribed, skipped, failed}` 三分类。
- **技术点**：**幂等性**（重复订阅静默跳过）、业务规则校验（拒绝过期合约、临近交割 ≤1 天）、错误原因结构化返回。
- **学到**：接口设计里的"三态结果"比"成功/失败"更有表达力。

### 2.4 C 路线：`tqdiff/auth.py`（认证 + 静态数据，211 行）

- **功能**：OAuth 登录 → 换行情地址 → 下载合约目录 → 数据解析。
- **技术点**：
  - **OAuth 密码模式**：`grant_type=password` 换 access_token（JWT）；
  - **流式下载**：`requests.get(stream=True)` + 逐块写临时文件 + 原子改名落盘 + 进度回调
    （实测下载 333MB 的合约文件，进度日志就是它打的）；
  - **磁盘缓存 TTL**：24 小时内直接读本地；
  - **解析器**：`parse_instrument_record`/`parse_kline_row` 纯函数，兼容字典/数组两种行格式，NaN 拒识。
- **学到**：HTTP 认证流程、大文件健壮下载、解析器与网络分离（可单测）。

### 2.5 C 路线：`tqdiff/client.py`（≈530 行，难度 ★★★★★，全项目技术天花板）

- **功能**：不用 TqSdk，直接实现天勤 DIFF 协议的行情客户端。
- **核心设计与解法**：
  - **线程里跑 asyncio**：`threading.Thread` + `asyncio.new_event_loop()` + `run_until_complete`
    ——为什么？（FastAPI 的事件循环不能被阻塞的同步 WebSocket 库干扰）；
  - **peek/rtn_data 协议循环**：收到数据回一条 `peek_message`，服务器才有动力继续推；
  - **命令即协程**：`run_coroutine_threadsafe(self._execute(...), loop)`——
    每个命令是独立协程并发执行，**没有共享队列**——与 AB 路线对比着学；
  - **增量 K 线合并**：`charts[(symbol, dur_ns)] = {rows, last_id, ready}`，
    DIFF 协议按行号增量给数据，客户端自己拼完整窗口（**增量同步**思想）；
  - **三个实战协议坑**（§2.4 已提）都有注释和回归测试——**协议逆向 + 抓包对比**方法论
    （用 TqSdk 的 `debug=` 参数抓真包对照）；
  - **断线重连循环**、**订阅快照重放**（休市也能显示）、**set_chart 轮询重发**（规避前置的静默丢弃）。
- **学到**：应用层网络协议实现、asyncio 并发模型、增量数据同步、抓包驱动的协议学习法。

### 2.6 `tq/__init__.py`、`tqdiff/__init__.py`

- 一行文档 + 导出。**包初始化文件**的规范用法。

## 3. 业务层 `market/`（纯函数天堂，新手从这里开始读）

### 3.1 `model.py`（78 行）

- **功能**：定义"标准行情"长什么样：`MarketQuote`（含五档盘口）、`Instrument`（合约元数据）。
- **技术点**：`@dataclass(frozen=True)`（不可变值对象）、`Optional[float]` 类型标注、`to_dict()` 序列化。
- **学到**：**数据契约**——上层只认识这层定义的结构，数据源随便换。这叫**防腐层**。

### 3.2 `processor.py`（77 行）

- **功能**：把数据源的 Quote 对象转成 `MarketQuote`。
- **技术点**：
  - `math.isfinite` 清洗 NaN/Inf（金融数据必做！一个 NaN 会让整条链路崩）；
  - 鸭子类型：任何"长得像 Quote 的对象"（含测试替身）都能转；
  - 五档截断：某一档为空就停（数据不撒谎）。
- **学到**：**归一化/清洗**是数据工程第一课。

### 3.3 `cache.py`（37 行）

- **功能**：线程安全的最新行情内存缓存。
- **技术点**：`threading.Lock` 保护共享 dict——**最简单的并发正确性**。
- **学到**：读写共享状态必须加锁；接口小而精（set/get/all/clear/len）。

### 3.4 `indicators.py`（131 行，最好的算法练习）

- **功能**：SMA/EMA/MACD/RSI/KDJ/BOLL/ATR 七个技术指标，纯 Python。
- **技术点**：
  - **Wilder 平滑**（RSI/ATR）：`avg = (avg*(n-1) + x)/n` 递推；
  - EMA 种子值用前 n 个均值，避免前段失真；
  - 数据不足返回 `None` 而不是 0——**不伪造数据**原则；
  - 全部是**纯函数**（输入列表→输出数值，无副作用）→ 极易单测。
- **学到**：公式→代码的翻译；为什么纯函数是可测试性的根基。

### 3.5 `evaluator.py`（387 行，业务核心）

- **功能**：多周期多因子评分 → 做多/做空/观望 + 止损/目标/手数。
- **技术点**：
  - **多因子加权**：趋势 40（排列/MACD/共振）+ 动量 25（突破/RSI/KDJ）+ 量仓 20 + 风险 15；
  - **死区阈值**：EMA 差 < 0.05% 视为粘合、MACD 差 < 0.1% 视为粘合——**防震荡误判**的工程手段；
  - **信号门槛**：≥60 分且多空差 ≥15 才给方向——宁可观望也不硬给信号；
  - **风险头寸公式**：手数 = 风险额 ÷ (止损距离 × 乘数)，止损 1.5×ATR 按 tick 取整，目标 1.5R/3R；
  - **评估依据**：每加一分都留下中文理由（`rationale`）——**可解释性**。
- **学到**：把交易经验变成可解释的规则引擎；权限/风险约束硬编码在公式里。

## 4. 接口层 `api/`

### 4.1 `http.py`（≈290 行）

- **功能**：所有 REST 接口 + 应用装配。
- **技术点**：
  - **应用工厂模式**：`create_app(config)` 返回配好的 FastAPI 实例（便于测试时造多个实例）；
  - **依赖注入**：`Depends(get_services)` 把运行时容器传进端点；
  - **lifespan**：启动时创建广播任务/启动行情客户端，关闭时优雅停止（**资源生命周期**）；
  - **async 端点 + `asyncio.to_thread` + `Semaphore(8)`**：阻塞调用丢线程池但限并发——
    防"线程池被超时请求占满→全站无响应"（本项目真实事故，见 docs/07）；
  - **异常处理器**：`@app.exception_handler(TqClientError)` 统一转 503+JSON；
  - Pydantic `BaseModel` 请求体校验。
- **学到**：现代 Web 框架的正确打开方式（工厂/DI/生命周期/限流/统一错误）。

### 4.2 `websocket.py`（93 行）

- **功能**：`/ws/market` 实时推送。
- **技术点**：
  - **共享连接**：所有客户端共用一条天勤连接，服务端广播——资源约束下的设计取舍；
  - `ConnectionManager`：连接集合 + asyncio.Lock；
  - 推送只在行情**变化**时发生（事件驱动，不轮询）；
  - 快照补发：订阅已存在（skipped）也发快照（修复休市时段页面空白）。
- **学到**：WebSocket 服务端协议设计（hello/subscribed/quote/snapshot/pong 消息类型）。

## 5. 前端 `static/`（无框架，最适合打基础）

### 5.1 `index.html`（110 行）

- **功能**：页面骨架：工具栏/报价头/三栏主体/状态栏 + 登录弹窗。
- **技术点**：语义化标签（header/section/aside/footer）、`id` 是 JS 的寻址锚点、
  静态资源 `?v=版本号` 防缓存、`<div class="modal hidden">` 弹窗结构。
- **学到**：HTML 是"骨架 + 把手"。

### 5.2 `style.css`（≈190 行）

- **功能**：行业风深色主题。
- **技术点**：CSS 变量（`:root { --up: #ef5350 }`）一键换主题；Flex 三栏布局；
  等宽字体显示价格数字；`.hidden` 工具类；滚动条美化。
- **学到**：设计系统 = 变量 + 少量工具类。

### 5.3 `app.js`（≈530 行，前端核心）

- **功能**：所有交互逻辑。
- **技术点**（每个都是面试题级别）：
  - **单一状态源**：`state` 对象是页面唯一记忆，所有渲染从它出发——"数据驱动 UI"的朴素版；
  - `fetchJSON`：`AbortController` 超时 + 外部信号合并 + 错误归一化；
  - **请求竞态防护**：`klineReq` 自增序号，响应回来对不上号就丢弃（解决"切合约后旧数据覆盖新数据"）；
  - **ECharts 多图联动**：3 个 grid（蜡烛/量仓/MACD）、`dataZoom` 缩放、`axisPointer.link` 十字光标联动、
    `markLine` 最新价虚线；
  - **WebSocket 重连**：断线 3 秒重连、订阅失败 5 秒重试、页面隐藏时不连（省资源）；
  - **轮询策略**：决策 6s / K线 15s / 状态 15s——按数据新鲜度需求定频率；
  - **搜索防抖**：300ms 才发请求；
  - localStorage 自选列表持久化。
- **学到**：不借助框架把"状态管理/竞态/重连/防抖"全写一遍，比背 Vue 概念受益终身。

## 6. 桌面壳 `electron/`

### 6.1 `main.js`（169 行）

- **功能**：开一个独立窗口装载网页；后端没起就自动拉起。
- **技术点**：
  - **主进程 vs 渲染进程**（Electron 双世界）；
  - `spawn("python", [LAUNCHER], {cwd, stdio:"ignore"})` 子进程管理；
  - **就绪探测循环**：每 500ms 探一次 `/api/v1/status`，最多 30 秒；
  - **谁创建谁清理**：`before-quit` 只杀自己拉起的子进程（不误杀用户自己跑的）；
  - 安全：`nodeIntegration:false + contextIsolation:true`；
  - 失败页：`data:text/html` 兜底提示。
- **学到**：桌面软件 = 窗口 + 进程管理 + 生命周期清理。

### 6.2 `package.json` / `启动桌面版.bat`

- npm 脚本与依赖声明；bat 里的 `chcp 65001`（UTF-8 编码）与 `%~dp0`（脚本所在目录）。

| `test_tqdiff.py` | 7 | 协议解析器（字典/数组双格式行、NaN 拒识） |

**测试设计心法**：
- 数据层全部用 FakeClient 替身 → 测试不碰网络，0.02 秒跑完；
- 合成数据有确定性扰动（`sin`/取模抖动），保证断言稳定；
- 边界优先：NaN、空列表、重复订阅、数据不足；
- "涨给做多、跌给做空、震荡给观望"——**用测试固化业务行为**。

## 12. 术语表（速查）

| 术语 | 一句话解释 |
|---|---|
| 防腐层 | 在你的系统和外部系统之间放一层翻译，外部的变化只影响这层 |
| 幂等 | 同一操作做多少次结果都一样（重复订阅不报错） |
| 活锁 | 系统没死但永远在无效忙碌（本项目 v1.1.1 的真实事故） |
| 竞态 | 两个操作比快慢，结果取决于时序（用序号/锁/取消解决） |
| TTL | 缓存的保质期（Time To Live） |
| Future | "还没好的结果"的凭据，可以等它，也可以超时放弃 |
| 协程 | 用户态的"轻量任务"，await 时让出控制权，不占线程 |
| 增量同步 | 只传变化的部分（DIFF 协议按行号给 K 线） |
| 死区/阈值 | 差异小于阈值视为"没变化"，防误判 |
| 纯函数 | 同输入必同输出、无副作用 → 最容易测试 |
| 测试替身 | 用假实现代替真依赖（FakeClient），让测试不碰网络 |
| 防腐层测试 | 先写测试固化行为，再改代码，红→绿 |
| 原子落盘 | 先写临时文件再改名，避免半截文件 |
| 信号门槛 | 分数不够就不给信号——宁可观望 |
