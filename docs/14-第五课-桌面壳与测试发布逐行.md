## 5.1 `electron/main.js`（169 行）逐段全解

### 5.1.1 引入与常量

```js
const { app, BrowserWindow } = require("electron");
const path = require("path");
const { spawn } = require("child_process");
```
- Node.js 用 `require` 导入（相当于 Python 的 import）；
- `app`：整个应用的生死；`BrowserWindow`：一个窗口的模具；
- `spawn`：启动一个**子进程**（相当于 Python 的 subprocess.Popen）。

```js
const SERVER_URL = "http://127.0.0.1:8000";
const PROJECT_DIR = path.join(__dirname, "..");
const LAUNCHER = path.join(PROJECT_DIR, "launcher.py");
```
`__dirname` 是"当前文件所在目录"（Node 自带变量）；`path.join` 跨平台拼路径（自动用 `\` 或 `/`）。

```js
let backendProcess = null;
```
记住"由我启动的后端"。**谁创建，谁负责清理**——如果后端是用户自己跑的，退出时不能误杀。

### 5.1.2 工具函数

```js
function sleep(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}
```
Promise 是 JS 的"还没好的结果"（= Python 的 Future）。`await sleep(500)` 就睡 500 毫秒。
`new Promise((resolve) => ...)`：造一个承诺，调用 `resolve()` 表示"办完了"。

```js
async function isServerUp() {
  try {
    const resp = await fetch(SERVER_URL + "/api/v1/status");
    return resp.ok;
  } catch (error) {
    return false;
  }
}
```
探活：能连上且状态码正常 → 活着；任何异常 → 没死透（**不关心为什么**，只要"活着/没活着"）。

### 5.1.3 ensureServer——守护进程三步曲

```js
async function ensureServer() {
  if (await isServerUp()) {
    console.log("[ZA量化] 检测到后端已运行");
    return true;
  }
  const child = spawn("python", [LAUNCHER], {
    cwd: PROJECT_DIR,
    stdio: "ignore",
  });
  backendProcess = child;

  for (let i = 0; i < 60; i++) {
    await sleep(500);
    if (await isServerUp()) {
      return true;
    }
  }
  child.kill();
  return false;
}
```
逐行：
1. 先探测——活着就直接用（**幂等**：不重复启动）；
2. `spawn("python", [脚本], {cwd})`：cwd=工作目录（launcher 在那里找 config.json）；
   `stdio: "ignore"`：子进程的输出直接丢弃（不污染主窗口终端）；
3. **轮询等待**：最多 60 次 × 0.5 秒 = 30 秒；
4. 超时杀掉子进程防残留，返回 false。
这就是"守护进程"最常见的写法：**检查 → 拉起 → 等待 → 确认（超时兜底）**。

### 5.1.4 创建窗口

```js
app.whenReady().then(async () => {
  const serverReady = await ensureServer();
  const win = new BrowserWindow({
    width: 1440, height: 900, minWidth: 1180, minHeight: 760,
    title: "ZA量化",
    icon: path.join(__dirname, "..", "assets", "icon.png"),
    autoHideMenuBar: true,
    webPreferences: { nodeIntegration: false, contextIsolation: true },
  });
```
- `whenReady`：Electron 初始化完成后执行；
- `webPreferences` 两项是**安全标配**：页面 JS 不能直接碰 Node 能力（防止网页代码干系统级坏事）。

```js
  if (serverReady) {
    await win.loadURL(SERVER_URL);
  } else {
    await win.loadURL("data:text/html;charset=utf-8," + encodeURIComponent(`<!DOCTYPE html>...`));
  }
```
后端没起来时不是白屏，而是显示一张**内联错误页**（data URL 直接塞 HTML），
告诉用户去检查 Python 依赖——**失败体验也是设计**。

```js
  win.on("page-title-updated", (event) => {
    event.preventDefault();
    win.setTitle("ZA量化");
  });
```
锁定窗口标题：网页标题变了也不改（保持品牌一致）。

### 5.1.5 退出清理

```js
app.on("window-all-closed", () => {
  if (process.platform !== "darwin") {
    app.quit();
  }
});

app.on("before-quit", () => {
  if (backendProcess) {
    backendProcess.kill();
    backendProcess = null;
  }
});
```
- 所有窗口关闭 → 退出应用（macOS 惯例不同，所以有判断）；
- **before-quit**：退出的最后一刻清理子进程（窗口关了但 python 可能还活着——必须杀）。

## 5.2 `electron/package.json` 与 `启动桌面版.bat`

```json
{ "main": "main.js", "scripts": { "start": "electron ." }, "devDependencies": { "electron": "^33.2.0" } }
```
`main` 告诉 Electron 入口在哪；`^33.2.0` 是**语义化版本**：允许 33.x 的更新，不许跳到 34。

```bat
chcp 65001 >nul
cd /d "%~dp0electron"
node_modules\.bin\electron.cmd .
```
- `chcp 65001`：把终端切到 UTF-8（否则中文乱码）；
- `%~dp0`：bat 文件自己所在的目录（双击运行时必须靠它定位）；
- `>nul`：把命令输出扔掉。

## 5.3 `tools/make_icon.py`（77 行）——程序化生成资源

```python
draw.rounded_rectangle((0, 0, size - 1, size - 1), radius=radius, fill=BG)
```
PIL 画图：圆角矩形当底板。

```python
    def polygon(points, outline, width, fill=None) -> None:
        draw.polygon(points, outline=outline, fill=fill)
        for i in range(len(points)):
            a, b = points[i], points[(i + 1) % len(points)]
            draw.line([a, b], fill=outline, width=max(1, int(width)))
```
`polygon` 的描边宽度受限 → **逐边再画一遍线加粗**。`(i + 1) % len(points)`：取模实现"回到第一个点"（闭合多边形）。
`math.sqrt(2)` 的来源：正方形旋转 45° 后顶点距离 = 半边长 × √2。

## 5.4 `ZA量化.spec`（PyInstaller 配方）

```python
a = Analysis(['launcher.py'], ..., datas=[('static', 'static'), ('config.json.example', '.'), ('VERSION', '.')], ...)
pyz = PYZ(a.pure)
exe = EXE(pyz, a.scripts, a.binaries, a.datas, ..., name='ZA量化-C直连版', console=True, icon=['assets/icon.ico'])
```
- `Analysis`：分析 launcher.py 依赖了哪些库，全部收进来；
- `datas`：把资源文件夹**塞进 exe**（运行时解压到 `sys._MEIPASS`）；
- `onefile`（命令行 --onefile）：所有东西合成一个 exe（启动时解压稍慢，但单文件好分发）；
- `console=True`：保留黑窗口看日志（桌面正式版可以改 False 隐藏）。

### 5.5.1 测试替身：`test_tq.py` 的 FakeClient

```python
class FakeClient:
    connected = True
    def __init__(self) -> None:
        self.commands: list[tuple[str, tuple]] = []
        self.subscribed: set[str] = set()

    def run_command(self, command: str, *args: object, timeout: float = 8.0) -> object:
        self.commands.append((command, args))
        if command == "get_instrument":
            key = str(args[0]).lower()
            if key not in VALID_LOWER:
                raise TqClientError(f"合约不存在：{key}")
            ...
```
**FakeClient 为什么成立？** 因为真实 TqClient 的公开接口只有一个 `run_command`——
上层（instruments/subscriber）只调它。所以造一个"行为像它"的假货，上层完全无感。
这就是第 2 课讲的**防腐层**带来的可测试性红利。

```python
    def test_subscribe_is_idempotent(self):
        first = self.manager.subscribe(["SHFE.rb2610", "rb2610"])
        self.assertEqual(first["subscribed"], ["SHFE.rb2610"])
        self.assertEqual(first["skipped"], [])
        second = self.manager.subscribe(["SHFE.rb2610", "SHFE.rb2610"])
        self.assertEqual(second["subscribed"], [])
        self.assertEqual(second["skipped"], ["SHFE.rb2610"])
```
**幂等性测试**：第一次请求里 `rb2610` 和 `SHFE.rb2610` 是同一个合约→去重成一次；
第二次再来→全是 skipped。**用断言把业务规则钉死**——以后谁改坏了这个行为，测试立刻红。

## 5.6 发布工程复盘（本次真实操作）

把软件发上 GitHub 的完整流程（你在本项目中看过真实执行）：

```
1. 核查敏感信息     git grep <密码> $(git rev-list --all)   # 必须 0 命中
2. 推送分支         git push -u origin master route-ab route-c
3. 打标签           git tag -a V1.1.1 <推荐主线的提交> && git push origin V1.1.1
4. 创建 Release     POST /repos/{owner}/{repo}/releases  （附说明+校验和）
5. 上传资产         POST uploads.github.com/.../assets?name=...  （exe 逐个传）
6. 收尾             设默认分支、写清资产与内部构建号的对应关系
```

学到的规范细节：
- **中文文件名会被 GitHub 清洗** → 资产用 ASCII 名（`ZAQuant-V1.1.1-C-Direct.exe`），
  在 Release 说明里写清与本地中文名的对应关系；
- **大小写不同的标签**在 Windows 本地会冲突（文件系统不区分大小写），但 GitHub 区分——
  别让 v1.1.1 和 V1.1.1 同时存在；
- **默认分支**要设成最重要的分支（新建仓库默认可能是 main/main 分支为空时的尴尬）；
- Release 说明里放 **SHA-256**：别人下载后可校验文件没被篡改。
