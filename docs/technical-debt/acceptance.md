## 第 4 步：订阅恢复与受管关闭

连接回调只唤醒一个恢复 worker；状态锁与网络操作锁分离。临时失败按 1、2、4、8、16、30 秒重试，明确无效合约结束；部分目录的排队订阅保留 pending，实际发送成功才确认。单调操作版本及别名取消记录阻止迟到恢复/退订覆盖新意图。最后一只退订发送空全局订阅表，同 DIFF loop 的同步命令立即报错。

桌面 lifespan 和 Android 服务销毁均进入受管关闭；取消 session、目录和命令任务，主动关闭 WS，停止恢复线程。Android 移除 import 自动启动，保留 Server 句柄及初始化前停止请求。线程实际退出才清理引用，重复启动/关闭幂等。DIFF 显式管理 HTTP executor，关闭等待已有 HTTP 工作自然完成；原 HTTP 超时不变，关闭等待超时保留旧线程，阻止第二条行情线程。不能立即终止已开始的 HTTP 工作。

验收：统一离线 Python 156 项通过（0.533 秒），含新增共享 20 项和 Android 12 项 Fake 场景；覆盖完整目录 cache-miss 回放不占 DIFF loop、临时失败、排队未确认、别名取消、迟到退订、新意图、空表、queued sync 单任务、受管任务取消、HTTP executor 释放及超时保留。共享文件漂移、现场冻结守卫、差异检查通过；修改的 Python 源码通过 Python 3.8 语法检查。未构建 APK、启动真实网关或操作现场服务，设备生命周期仍留待独立构建任务验证。

## 第 5 步：连接与广播背压

两端共享连接管理，健康后台连接保留、后台断线暂停重连，前台按需连接。连接、回调和计时器由身份/版本守卫；退避 3、6、12、24、30 秒，失败 ACK 驱动的订阅重试最多 6 次，重复 ACK 不重置预算。手机删除非当前项先更新订阅意图并取消旧 timer，再发原退订。

两端共享标准库传输：每连接一个 sender、128 条 FIFO、发送超时 2 秒；慢连接溢出/超时关闭码 1013，控制回复明确成功或失败，quote.ts 在实际发送时生成。握手前登记生命周期，关闭取消未完成握手；已摘除连接的关闭任务仍受管，close_all 等待完成。Android 接入相同组件，接口 stub 未覆盖。

入口容量 1024，每批最多 256，单待执行唤醒，过载丢最旧待推送行情并限频记录累计计数。每笔行情仍先更新原缓存和接收统计。专项测试覆盖 4 线程突发、快慢连接隔离、控制回复、FIFO、关闭竞态及无残留任务。

验收：完整 Python 165 项通过；Node 连接与双端一致性测试通过；双端离线浏览器测试通过，包括真实图表缩放和旧连接报价失效。严格漂移、冻结/现场守卫与差异检查通过。未运行现场服务或构建 APK。
