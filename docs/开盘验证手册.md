# 开盘实盘验证手册（runbook）

> 目的：交易时段内**一条命令拿齐全部 P0 验收数据**（真实行情/五周期 K 线/K 线实时性/200ms 延迟/手机端），
> 证据自动落盘 `docs/验证记录/<日期>/`，可直接回填 `docs/待办与验收计划-2026-09-11.md`。
>
> 前置：桌面后端已启动且天勤已连接（`python launcher.py` 或 `dist\ZA量化-C直连版.exe` 或 `cd electron && npm start`）。

## 一、电脑端（主力，全自动）

```bash
# 0) 开跑前体检（后端/连接/目录/交易时段），几秒出结果
python tools/live_verify.py preflight

# 1) 全流程（默认：K线实时性采样 3 分钟 + 延迟采样 10 分钟，约 13 分钟）
python tools/live_verify.py all

# 快速抽查（K线 1 分钟 + 延迟 30 秒）
python tools/live_verify.py all --minutes 1 --interval 8 --seconds 30

# 换合约 / 换 K 线周期（all 默认逐周期验收 1分/5分/日线 三档）
python tools/live_verify.py all --symbol SHFE.au2612
python tools/live_verify.py all --periods 60 900          # 自选周期组合逐周期验收
python tools/live_verify.py kline-live --periods 300 --minutes 5
python tools/live_verify.py kline-live --periods 60 300 1800 3600 86400 --minutes 5   # 全周期一遍过
```

单项跑法：

| 命令 | 验收项 |
|---|---|
| `python tools/live_verify.py quote` | P0 报价：最新/量/持仓/五档字段 |
| `python tools/live_verify.py kline-history` | P0 五周期历史 K 线（非空/升序/字段有效） |
| `python tools/live_verify.py kline-live --minutes 3` | P0 **K 线实时性**（形成中 K 线会变、新 K 线会出现） |
| `python tools/live_verify.py latency --seconds 600` | P0 **200ms 延迟**（p95，样本 ≥30 才判定） |
| `python tools/live_verify.py report` | 汇总当天证据为 `报告.md` |

## 二、手机端（真机 USB 连接后）

```bash
# 手机装最新 APK、打开 App 并登录 → USB 连电脑（开 USB 调试）→：
python tools/live_verify.py phone            # 后端状态 + K线两次采样对比 + logcat + 截图
python tools/live_verify.py phone --gap 60   # 拉长观察间隔（看 1 分钟 K 线跨根）
```

原理：`adb forward tcp:18000 → 手机 127.0.0.1:8000`，直接读手机内后端的 K 线数据——
**手机界面画的就是这份数据**，末根 K 线在变 = 手机端实时性正常。
配合界面观察：K 线页停留观察，最新一根 1 分钟 K 线应随行情"长高"，每分钟出新根。

## 三、判定语义（防止误判）

| 判定 | 含义 |
|---|---|
| **PASS** | 行情活跃（时间戳/成交量在变）且 K 线持续更新 / p95 ≤ 200ms 且样本 ≥30 |
| **FAIL** | 行情活跃但 K 线不动（推送/合并/解析停滞——真 bug，配合 `TQ_GATEWAY_DEBUG=1` 抓）；或 p95 > 200ms |
| **INCONCLUSIVE** | 无新行情（休市/无成交）或样本不足——**不算失败**，换时段再测 |

> 周期性快照刷新（周末也能收到）**不**算"新行情"，判定用行情时间戳/成交量是否真正变化。

## 四、Monday 标准流程（照抄即可）

1. `python tools/live_verify.py preflight` —— 确认连接/目录就绪/交易时段
2. `python tools/live_verify.py all` —— 电脑端全量（期间可同时观察桌面 K 线页是否实时跳动）
3. 手机装 `dist/ZA量化-手机版-v1.1.1.apk` → 登录 → USB 连接 → `python tools/live_verify.py phone`
4. `python tools/live_verify.py report` —— 生成 `docs/验证记录/<日期>/报告.md`
5. 把报告里的 PASS/FAIL 与数据回填 `docs/待办与验收计划-2026-09-11.md` 对应条目

## 五、若 FAIL 的定位手段

- 后端启动时带 `TQ_GATEWAY_DEBUG=1`：K 线全链路结构化日志（`[kline #id]` 各阶段耗时/行数/异常）
- `electron/backend.log`（桌面壳拉起的后端）或 launcher 控制台
- `docs/验证记录/<日期>/kline_live.json` 的 timeline 能看出"从哪一秒开始停滞"
