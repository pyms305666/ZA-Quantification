# V1.3.1 合约查询修复

日期：2026-10-27（Asia/Shanghai）。用户实测 Android 后反馈搜索“烧碱”失败，随后确认电脑也存在此前指定合约查不到的情况；此轮双端修复与此前按需搜索改动一并作为 1.3.1。

## 实测原因

截图显示行情已连接、报价可见，但搜索提示“天勤合约查询失败”。公开合约服务上的只读复现得到：

```text
failed to execute graphql operation, errors: [variable does not have the key: products ]
```

此前固定 GraphQL 模板声明了 `classes/exchanges/products/symbols/expired` 五个变量，而主连名称查询只传 `classes`。天勤实际实现要求每个已声明变量都有值；之前的模拟器没有检查这条约束。直接把未用条件填成 null 的尝试也没有取得成功响应。

修复为根据本次实际条件生成变量声明和参数，参数名/类型由白名单决定，用户输入仍只作为变量值传递。上游失败的详细原因保留在日志，界面显示可读提示。

真实返回还确认了 `expire_datetime` 的单位是纳秒；旧静态合约解析器使用秒。现在在 GraphQL 适配边界转换成秒，再计算到期剩余天数和过滤已到期合约。
