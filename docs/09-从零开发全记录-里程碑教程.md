# 从零开发全记录：ZA量化 里程碑教程（docs/09）

> 本教程回答一个问题：**如果一切从空文件夹开始，怎么把这套软件一步步造出来？**
> 它不是成品代码的复读，而是**开发顺序的设计**——这才是软件工程和"会写代码"的区别。
>
> **核心方法论（先背下来）**：
> 1. **增量式开发**：永远保持"上一步是能跑的"。每一步结束都有一个可运行、可验证的东西。
> 2. **行走骨架优先**（Walking Skeleton）：第一周就打通"前端→接口→数据"最细的一条线，
>    哪怕丑得没法看。骨架通了，后面全是往上长肉。
> 3. **探针脚本先行**（Spike）：接任何第三方/协议之前，先写一个 20 行的一次性脚本验证"能不能拿到数据"，
>    扔了也不心疼。**绝不在没验证过的假设上盖大楼**（本项目 C 路线的三个协议坑就是靠探针发现的）。
> 4. **测试先行**：业务逻辑（指标/评分）先写测试再写实现；边界（NaN/空/重复）优先。
> 5. **小步提交**：每个里程碑一个 commit，信息写"做了什么+为什么"。这是你的时光机。

## M0：环境与仓库（半天）

🎯 目标：`python -V` 能跑、项目文件夹变成 git 仓库。

1. 安装 Python 3.11+（勾选 Add to PATH）、VS Code、Git。
2. 建虚拟环境（**隔离依赖，避免污染全局**）：
   ```powershell
   python -m venv .venv
   .venv\Scripts\activate          # 每次开发先激活
   ```
3. `git init`，先写 `.gitignore`（第一版只要 4 行）：
   ```
   .venv/
   __pycache__/
   config.json
   .tqsdk/
   ```
   为什么第一天就写它？——**等你想起来的时候密码已经提交了**（先防守后进攻）。
4. 第一个提交：`git commit -m "chore: 项目初始化（venv + gitignore）"`。

✅ 验收：`git log` 有一条记录；`python -V` 在激活的 venv 里执行。

## M4：行情线程 + 命令队列（2~3 天，全项目最硬的一课）

🎯 目标：行情逻辑搬进独立线程，HTTP 线程能安全地"点菜"。

**为什么要线程？** TqSdk 不是线程安全的：多线程同时调 `wait_update` 会炸。
**为什么不能直接加锁了事？** `wait_update` 一等就是几百毫秒，锁住它=把所有请求卡死。
**解法**：唯一线程拥有 TqApi，其他线程把"命令"排队：

```python
class _Cmd:
    __slots__ = ("command", "args", "future", "abandoned")
    def __init__(self, command, args, future):
        self.command, self.args, self.future = command, args, future
        self.abandoned = False                      # 等待方超时可标记放弃

class TqClient:
    def __init__(self):
        self._commands = queue.Queue()

    def run_command(self, command, *args, timeout=8.0):
        cmd = _Cmd(command, args, Future())
        self._commands.put(cmd)
        try:
            return cmd.future.result(timeout=timeout)   # 阻塞等结果
        except TimeoutError:
            cmd.abandoned = True                        # 超时不取消执行方……
            raise TqClientError(f"命令超时：{command}")

    def _run(self):                     # 事件循环线程
        api = self._connect()
        while not self._stop.is_set():
            api.wait_update(deadline=time.time() + 0.5)   # 驱动 tqsdk
            self._process_commands(api)                   # 处理排队的命令
            self._dispatch_changes(api)                   # 派发行情变化
```

🧩 概念：**生产者-消费者**、`Future`（还没好的结果的凭据）、**为什么超时后要标记放弃**。
✅ 验收：两个终端同时 curl `/status`，互不卡死；主程序 Ctrl+C 能干净退出。
⚠️ 坑（本项目真实事故）：命令超时后如果不标记放弃，队列里堆满"执行了也白执行"的命令——活锁的种子。

## M5：缓存 + 前两个真接口（1 天）

🎯 目标：`/status` 显示连接状态；`/quote/SHFE.rb2610` 返回五档行情 JSON。

```python
# market/cache.py —— 37 行教你并发正确性
class QuoteCache:
    def __init__(self):
        self._data, self._lock = {}, threading.Lock()
    def set(self, quote):
        with self._lock:                    # 共享状态必须加锁
            self._data[quote.symbol] = quote
```

```python
# api/http.py —— 依赖注入雏形
@app.get("/api/v1/quote/{symbol}")
def quote(symbol: str):
    cached = services.cache.get(symbol)
    if cached:
        return {"data": cached.to_dict(), "pending": False}
    ...   # 没有就触发订阅，返回 pending:true
```

🧩 概念：**TTL 缓存思路**、**pending 语义**（还没拿到≠失败）、FastAPI `Depends`。
✅ 验收：交易时段 curl 能看到 last/五档；断网时返回中文错误而不是 500。

## M6：K 线接口（1 天 + 一个重要教训）

🎯 目标：`/kline/SHFE.rb2610?period=300&count=50` 返回标准化的 K 线数组。

关键代码（成品在 `tq/client.py _get_kline`）：
- `get_kline_serial(..., deadline=...)` **必须带 deadline**——否则服务器慢响应会永远阻塞事件循环（项目真实踩坑）；
- 统一取 400 根再切片返回 count 根——**固定长度复用内部缓存**；
- 返回前清洗：`datetime` 纳秒→毫秒、NaN→None。

🧩 概念：第三方调用的**防御性参数**；数据标准化。
✅ 验收：返回的最后一根 K 线时间与交易时段吻合。

## M7：指标库（2 天，测试先行示范）

🎯 目标：7 个指标全部由测试驱动写出。

流程示范（SMA）：
```python
# 先写测试
def test_sma(self):
    self.assertEqual(sma([1, 2, 3, 4], 3), 3.0)     # (2+3+4)/3
    self.assertIsNone(sma([1, 2], 3))               # 数据不足返回 None
# 再写实现
def sma(values, period):
    if len(values) < period or period <= 0:
        return None                                  # 不伪造数据
    return sum(values[-period:]) / period
```

MACD/RSI/ATR 同法：**手算 3 个数 → 写断言 → 写递推 → 绿**。
🧩 概念：纯函数、Wilder 平滑递推、`None` 表达"不可知"。
✅ 验收：测试数 ≥ 10，全绿；常量序列的 EMA 等于常数（性质断言）。

## M14：加固迭代——真实事故回放课（持续）

这三个事故是**上线后才发现**的，完整复盘在 docs/07。从零重做时把它们当"必修考试题"：

| 事故 | 症状 | 根因 | 修复教具 |
|---|---|---|---|
| 首屏活锁 | 打开页面全超时、服务无响应 | 长查询独占单线程 + 线程池耗尽 | 目录后台协程、Semaphore 限流、可放弃命令 |
| 超时丢弃 | 目录缓存永远建不起来 | 查询 140s > 超时 120s | 结果写回与等待方解耦 |
| 冷启动崩溃 | 盘口/决策全挂 | Event 误当 awaitable | 冷启动必须真实测试 |

## 与成品对照的学习法

每个里程碑做完，打开对应成品文件**对比你的实现**，重点看三件事：
1. 它比你多考虑了什么边界？（NaN/超时/重连/冷却）
2. 它的结构为什么那样拆？（函数粒度、钩子、dataclass）
3. 它的注释在解释"为什么"还是在复述"是什么"？（前者才值得写）
