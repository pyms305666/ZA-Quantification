## 4. 发现的问题

### P1：手机端没有完成真机验证

**现象：** 本机没有 `adb`，没有可连接的 Android 设备或模拟器，也没有移动端自动化测试目录。

**无法确认的内容：**

- App 是否能正常启动 WebView；
- Chaquopy 后端是否在真实 Android 进程中成功监听 8000；
- 登录界面和行情页面是否正常显示；
- 网络权限、证书、WebSocket、行情更新是否正常；
- 返回桌面、旋转屏幕、进程重启后是否能恢复。

**建议：** 使用 Android Studio/模拟器或实体手机安装 `app-debug.apk`，执行启动、登录、订阅、K 线、断网重连和退出重启测试，并保存 Logcat。

### P1：真实行情链路未在本轮重新验收

单元测试和应用装配不等于真实行情验证。本轮没有使用账号执行 OAuth、名称服务、WebSocket `subscribe_quote`、`set_chart` 和历史 K 线请求。

此前调试记录中实时行情有成功样例，但历史 K 线出现过 `HISTORY_EMPTY`。因此当前不能宣称实时行情持续更新、历史 K 线完整或端到端 200ms 更新目标已经达成。

### P1：Android Chaquopy 使用的 Python 版本与本机构建 Python 不匹配

Gradle 构建过程中出现：

```text
Warning: Failed to compile to .pyc format: buildPython version 3.13.5 is incompatible
```

构建仍然成功，但 Python 字节码预编译被跳过，可能增加首次启动时间和运行时解析开销。建议使用 Chaquopy 支持的 Python 版本配置 `buildPython`，或确认该警告在目标版本中可接受。

### P1：Electron 后端启动失败时诊断信息不足

`electron/main.js` 中后端子进程使用：

```javascript
stdio: "ignore"
```

因此 Python 启动错误不会被 Electron 直接记录。用户看到的可能只是 30 秒超时页面，无法知道是 Python 不存在、依赖缺失、配置错误还是行情认证失败。

建议把 stdout/stderr 写入日志文件或转发到主进程日志，并处理子进程 `error`、`exit` 和启动码。

### P2：Electron 使用了未声明的隐式全局变量

`main.js` 中直接给 `portBlockedBy` 赋值，但没有看到模块级 `let`/`const` 声明。当前因为没有严格模式，语法检查仍通过；这会造成状态残留和维护风险，未来启用严格模式时会直接抛错。

建议声明并在每次 `ensureServer()` 开始时重置，例如：

```javascript
let portBlockedBy = null;
```

### P2：桌面端和手机端 Python 代码双份且已经分叉

桌面端 `tqdiff/` 与手机端 `mobile-app/app/src/main/python/tqdiff/` 的认证、合约缓存和流式索引实现不同。手机端有 `symbol_index.py`，桌面端没有；尝试导入 `tqdiff.symbol_index` 时桌面端失败。

这不是当前 C 桌面路线启动必然失败的证据，因为桌面端当前认证逻辑没有直接导入该模块，但它说明两端协议实现已经分叉，后续修 bug 时容易只修一边。

建议抽取共享核心包，或至少增加桌面/手机 API 契约测试和差异检查。

### P2：Android Gradle 仍有弃用警告

已有 Gradle 问题报告记录了 3 个问题，包括：

- `mobile-app/build.gradle` 使用 Groovy 空格赋值语法；
- Android 插件依赖使用多字符串形式；
- 这些写法在未来 Gradle 版本中可能升级为错误。

本次 Android 构建使用 Gradle 8.9 成功，但不代表未来 Gradle 9/10 仍可构建。建议按报告提示改为显式 `property = value` 和单字符串依赖声明。

### P2：Android 原工程缺少完整 Gradle Wrapper 脚本

项目中只有 `mobile-app/gradle/wrapper/gradle-wrapper.properties`，缺少 `mobile-app/gradlew`、`mobile-app/gradlew.bat` 和 wrapper JAR。因此本次构建依赖本机缓存的 Gradle 8.9，换到干净机器不能直接执行 `gradlew assembleDebug`。

建议补齐并提交标准 Gradle Wrapper 文件，或者在项目文档中明确构建机要求。

### P2：本地配置存在明文凭据风险

当前 `config.json` 和配置逻辑支持把账号密码写入本机 JSON；虽然 `config.json` 和 `.tqsdk/` 已被 `.gitignore` 排除，但本机文件仍是明文。报告不写出具体账号密码。

建议优先使用环境变量，后续改用 Windows Credential Manager、Android Keystore 或其他系统安全存储。

### P2：APK 的网络和 WebView 配置缺少真机安全验收

Android Manifest 开启了 `usesCleartextTraffic="true"`，同时 WebView 访问本机 HTTP 服务。这对当前本机回环通信有实际用途，但需要在真机上确认不会导致错误页面或安全策略问题；不应把该配置扩展到外部 HTTP 行情地址。

### P3：缺少端到端、性能和回归测试

当前 43 个测试主要是纯 Python 单元测试，没有覆盖：

- FastAPI HTTP 路由实际响应；
- WebSocket 订阅/推送；
- Electron 页面加载；
- Android Activity 生命周期；
- 200ms 更新延迟；
- 多合约并发订阅；
- 网络断开、重连和服务端错误。
