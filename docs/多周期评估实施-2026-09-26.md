# 多周期评估实施说明

日期：2026-09-26。适用于本次源码修改；界面验证使用合成行情，不代表实际交易表现。

## 使用方法

桌面右侧评估栏、手机“决策”页均提供四档模式。选择模式后自动重新评估，K 线图表周期保持独立。展开“本档风险设置”后填写参数并保存；快速切换时会清除旧结果，过时请求不得覆盖新模式。

| 模式 | 计划持有时间 | 执行与 ATR 周期 | 确认周期 | 趋势周期 |
|---|---|---|---|---|
| 超短线 `ultra` | 5–30 分钟，不隔夜 | 1 分钟 | 5 分钟 | 15 分钟 |
| 短线 `short` | 1–3 个交易日 | 15 分钟 | 60 分钟 | 日线 |
| 中线 `medium` | 2–4 周 | 60 分钟 | 日线 | 周线 |
| 长线 `long` | 1–3 个月 | 日线 | 日线 | 周线 |

默认选择短线。持有时间是用户计划，系统不负责计时退出或自动平仓，也不保证在该时间内达到目标。

## 评估与数据

- 沿用趋势、动量、量价持仓和风险四类评分，各模式改用对应周期数据；量价持仓比较使用该模式的执行周期。
- 当前四档方向门槛均为总分至少 60、多空分差至少 15；止损距离为执行周期 ATR 的 1.5 倍且至少 2 个最小跳动，目标为实际止损距离的 1.5R / 3R。价格按最小跳动取整。参数在模式配置中分别定义，尚未经过策略回测校准。
- 分钟 K 线排除尚未结束的柱；日线保守排除当天柱，即使当天已收盘；周线由当前实际合约日线聚合，排除当前周和数据窗口首个可能不完整的周。
- 执行周期最低 30 根、确认周期最低 60 根、趋势周期最低 60 根；周线趋势使用 EMA10/20 与 MACD，最低 35 根完整周线。同周期重复使用时取更严格的数据要求。
- 中长线请求 400 根日线并聚合周线。新上市或历史较短的合约可能不足，返回缺少的周期及数量，暂不评估；不会拼接连续合约或用其他合约补齐。
- 显示行情时间、实际分析周期、风险预算和提示。报价过期、常规时段之外、合约已到期或距到期不足一天时，可以保留技术方向和价位，但不提供当前开仓手数。报价有效期分别为 60 / 180 / 300 / 300 秒。

## 每档风险

各档初始值来自后端默认配置：账户权益 50,000 元、单笔金额上限 900 元、权益比例上限 1.8%、最大 10 手。用户可逐档修改。

```text
风险预算 = min(单笔金额上限, 账户权益 × 权益比例 / 100)
一手预计止损金额 = abs(参考入场价 - 取整后的止损价) × 合约乘数
建议手数 = min(最大手数, floor(风险预算 / 一手预计止损金额))
预计止损金额 = 建议手数 × 一手预计止损金额
```

一手超过预算时显示 0 手和“不宜开仓”；合约乘数或最小跳动缺失时不猜测参数。界面金额不包含手续费、滑点和跳空，不能作为亏损保证，也未加入保证金可用余额约束。

四档设置和选中模式存放在本设备浏览器/WebView 的 `localStorage`，键为 `za-decision-profiles-v1`。桌面与手机不自动同步，清除站点或应用数据会删除设置。本地保存失败时界面明确提示。服务端按请求计算，不改写全局账户配置。

## 时段与到期提示

- 使用行情源 `trading_time.day/night`，支持跨午夜以及 `25:00:00` 表示法。超短线距当前时段收盘不足 30 分钟时提醒，少于 5 分钟仍展示方向并提示持有时间不足。
- 时段是常规日夜盘安排，尚未接入交易所节假日日历。短线到期覆盖检查使用 7 个自然日近似 3 个交易日；长线使用 93 个自然日近似 3 个月，节假日及实际月份可能造成差异。
- 到期倒计时依赖绝对 `expire_datetime`，不信任旧目录缓存中的相对天数。旧缓存未含绝对到期日且报价也未提供时，会显示无法确认的提示，待目录更新后取得该字段。
- 系统评估当前合约，不自动换月。交割资格和经纪商提前平仓期限需另外确认；交易时段或到期元数据缺失时明确提示。

行情字段定义参考：[天勤 Quote / TradingTime 官方文档](https://doc.shinnytech.com/tqsdk/latest/reference/tqsdk.objs.html)。

## API 与代码入口

`GET /api/v1/decision-profiles` 返回默认模式、四档定义、风险默认值和输入范围，不返回凭据。

示例：

```http
GET /api/v1/decision/SHFE.rb2705?mode=short&account_equity=50000&max_loss_per_trade=900&risk_percent=1.8&max_contracts=10
```

非法模式、非有限数字、范围越界或非整数最大手数返回 HTTP 422。省略 `mode` 保留旧 API 的综合周期，但风险额度和零手数修正同样生效。响应增加 `mode`、`holding`、`periods`、`warnings`、`session`、`quote_fresh`、`data_requirements`；正常评估还返回 `risk_budget` 和 `one_lot_risk`，`risk_amount` 表示按建议手数计算的预计金额。

| 文件 | 职责 |
|---|---|
| `market/decision_profiles.py` | 模式配置、输入检查、完整 K 线、周线聚合、时段和到期元数据 |
| `market/evaluator.py` | 模式评分、风险预算、止损和手数 |
| `api/http.py` / 手机 `mobile_api.py` | 请求解析与按需取数 |
| `static/decision-controls.js` / `.css` | 两端共用模式控件、保存、请求和解释信息 |
| 两端 `static/app.js` | 结果渲染及防止旧响应覆盖 |
| `tools/check_core_drift.py` | 核心及共用控件镜像一致性检查 |
