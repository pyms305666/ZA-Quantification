## 6.2 状态对象 state：整个页面的"记忆"

```js
const state = {
  symbol: "SHFE.rb2610",   // 当前在看哪个合约
  period: 300,             // 当前K线周期（秒）
  kline: [],               // K线数据（数组）
  quote: null,             // 最新行情（对象，null=还没有）
  decision: null,          // 决策结果
  ws: null,                // WebSocket 连接
  instruments: [],         // 合约列表
  exchange: "",            // 交易所过滤
  watchlist: [...],        // 自选列表
};
```

**理解 state 是理解整个前端的关键**：页面上的数据都存在这里，
哪个函数需要数据就从 state 拿，改完数据后调用对应的"渲染函数"刷新界面。

## 6.3 数据流（最重要的一张图）

```
【初始加载】init()
   │
   ├─► loadStatus()       ──fetch──► /api/v1/status      ──► 更新右上角连接状态
   ├─► loadInstruments()  ──fetch──► /api/v1/instruments  ──► 渲染左侧合约列表
   ├─► loadKline()        ──fetch──► /api/v1/kline/...    ──► 渲染K线图
   ├─► loadDecision()     ──fetch──► /api/v1/decision/... ──► 渲染右侧决策面板
   └─► connectWS()        ──ws────► /ws/market            ──► 实时行情 → 盘口/报价

【用户操作】切换合约 switchSymbol()
   ├─► 改 state.symbol
   ├─► 通知后端换订阅（ws.send）
   └─► 重新走一遍 loadKline / loadDecision / 拉行情

【定时刷新】每 6 秒 loadDecision；每 15 秒 loadKline/loadStatus
【实时推送】WebSocket 每有行情变化 → 更新 state.quote → renderQuoteBar + renderDepth
```

**核心心法：数据统一进 state，界面永远由 state 渲染**。
这样不管数据是"定时拉的"还是"推送来的"，界面都不会乱。

## 6.4 逐段导读

### ① 工具函数 `fetchJSON`（第 3 章讲过，现在看完整版）

```js
async function fetchJSON(url, options, timeoutMs = 30000) {
  const controller = new AbortController();        // 超时控制器
  const timer = setTimeout(() => controller.abort(), timeoutMs);  // 超时自动取消
  try {
    const resp = await fetch(url, { ...(options || {}), signal: controller.signal });
    const body = await resp.json().catch(() => ({}));   // 解析失败就给空对象
    if (!resp.ok) throw new Error(body.detail || `HTTP ${resp.status}`);
    return body;
  } finally {
    clearTimeout(timer);    // 请求结束，取消定时器
  }
}
```

**新增知识点**：
- `AbortController`：给 fetch 装一个"超时炸弹"，到时间自动炸（取消请求），防止页面一直转圈
- `finally`：无论成功失败都会执行的代码块（这里清掉定时器）
- `body.detail`：后端 FastAPI 报错时，错误信息放在 `detail` 字段里（你可以故意访问一个错的地址看看）

### ② 渲染合约列表 `renderContractList`

```js
function renderContractList() {
  const list = document.getElementById("contract-list");   // 找到列表容器
  list.innerHTML = "";                                     // 清空（防止重复）
  for (const item of state.instruments) {                  // 遍历所有合约
    const row = document.createElement("div");             // 新建一个 div（一行）
    row.className = "contract-item";                       // 给它套样式
    row.innerHTML = `<span>${item.name}</span><span>${item.instrument_id}</span>`;
    row.addEventListener("click", () => switchSymbol(item.symbol));  // 点击切换
    list.appendChild(row);                                 // 把这一行放进列表
  }
}
```

**新增知识点**：
- `createElement` / `appendChild`：JS 动态创建界面元素（之前我们只改文字，这里是"造元素"）
- 模板字符串：`` `文字 ${变量} 文字` `` —— 把变量拼进字符串（比 + 拼接好看）
- **渲染列表的标准套路**：清空 → 遍历数据 → 每个数据造一行 → 挂到容器上

### ③ 切换合约 `switchSymbol`

```js
async function switchSymbol(symbol) {
  state.symbol = symbol;              // 1) 记录当前合约
  state.quote = null;                 // 2) 清掉旧行情
  state.decision = null;              // 3) 清掉旧决策
  if (state.ws && state.ws.readyState === 1) {          // 4) WS 还连着吗？
    state.ws.send(JSON.stringify({ action: "subscribe", symbols: [symbol] }));  // 换订阅
  }
  await loadKline();                  // 5) 重新拉K线（await：等它拉完）
  loadDecision();                     // 6) 重新评估（不用等）
}
```

**注意**：第 5 步用了 `await`（等 K 线拉完），第 6 步没有（决策可以慢慢来）——
**async/await 可以控制"要不要等"**，这是异步编程的精髓。

### ④ WebSocket 收行情（第 3 章讲过，看完整版）

```js
ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.type === "quote" || msg.type === "quote_snapshot") {
    if (msg.symbol !== state.symbol) return;   // 不是当前合约就忽略（多合约订阅时很有用）
    state.quote = msg.data;                     // 存进 state
    renderQuoteBar();                           // 刷新报价头
    renderDepth();                              // 刷新盘口
  }
};
```

**为什么用 WebSocket 而不是每 200ms fetch 一次？** 因为行情每秒钟变好几次，
WebSocket 是"后端主动推"，网络开销小、实时性强。这也解释了为什么盘口跳得那么快。
