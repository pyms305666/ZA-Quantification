# 移动端锁屏保活与增量合约目录设计

## 目标

修复 Android 移动端的两个真机缺陷：

1. vivo V2528A（Android 16）锁屏后会冻结应用进程。即使 `BackendService` 已是
   `dataSync` 前台服务，进程仍显示为 `isFrozen=true`，本地后端 HTTP 在 8 秒内超时。
2. 合约目录下载或增量解析期间，合法合约可能尚未出现在本地目录中；当前代码将此
   情况误判为“合约不存在”，例如冷启动时拒绝 `SHFE.au2612`。

移动端的默认产品行为是：应用运行期间，即使锁屏也持续接收行情。

## 范围

本次只变更 Android 服务保活和 C 路线合约目录的状态语义。行情协议、订阅接口、
Web 页面交互及桌面端发布流程不变。

根目录 Python 核心与 `mobile-app/app/src/main/python` 镜像必须保持一致，并通过
`tools/check_core_drift.py --strict` 验证。

## 方案选择

采用“前台服务 + PARTIAL_WAKE_LOCK + 电池优化白名单引导”。

前台服务继续提供可见的持续运行通知。服务启动后取得部分唤醒锁，使 CPU 在锁屏时
保持可调度；服务终止时无条件释放。首次启动时检查系统是否已忽略本应用的电池优化，
未忽略时请求系统授权；若设备或系统拒绝请求，则保活仍依赖前台服务和唤醒锁，界面
给出进入系统“不受限制”电池设置的可操作提示。

不采用仅前台服务或仅唤醒锁的方案：真机已证明前台服务不足，而单独唤醒锁也没有
前台服务的用户可见性和 Android 后台执行保证。也不将保活开关默认关闭，因为这与
锁屏持续行情的产品决策相冲突。

## Android 服务设计

`MainActivity` 使用 `startForegroundService` 启动 `BackendService`，满足 Android O+
对于前台服务启动的时限要求。`BackendService` 在 `onCreate` 中先创建通知并调用
`startForeground`，再取得 `PowerManager.PARTIAL_WAKE_LOCK` 和启动 Python 后端。

唤醒锁使用不可引用计数的单一实例，服务内部维护其持有状态，避免重复启动服务时
叠加持有。`onDestroy` 始终释放已持有的锁；异常启动路径也必须释放，或停止服务。
服务继续返回 `START_STICKY`，让系统在被回收后请求重建。

Manifest 增加 `WAKE_LOCK` 与电池优化请求所需权限；既有前台服务权限、通知权限和
`dataSync` 类型保留。电池优化检查使用 `PowerManager.isIgnoringBatteryOptimizations`，
只在未授予时以应用包名发起系统授权 Intent；不轮询或重复弹窗。

此策略会增加待机耗电，属于用户已确认的默认持续行情行为。应用结束、服务被销毁或
启动失败后，锁必须释放。

## 合约目录状态机

将单一的 `_file_loaded` 概念拆为两个独立状态：

| 状态 | 含义 | 用途 |
| --- | --- | --- |
| `catalog_search_ready` | 内置表、缓存或增量解析已有可用记录 | 搜索和展示已出现的合约 |
| `catalog_complete` | 完整目录已下载并解析完成，或已加载完整缓存 | 对本地未命中的合约作严格拒绝 |

内置精简目录和增量解析到 1000 条时只能设置 `catalog_search_ready`。完整下载成功后，
替换目录并设置 `catalog_complete`。完整缓存加载时，两个状态同时设置。完整下载失败时
保留搜索状态，但不把目录升级为完整状态。

`get_instrument` 在目录未完整时，对未命中的规范合约返回“目录尚未完整”的可恢复错误，
而非 `SymbolNotFoundError`。订阅层因此允许该合约进入行情订阅，由行情服务最终校验。
当目录完整时，未命中才产生 `SymbolNotFoundError` 并被订阅层严格拒绝。已命中的过期
合约仍按现有规则拒绝。

状态接口中现有 `catalog_ready` 保持兼容并代表“可搜索”；新增完整状态仅供内部严格
校验与状态展示使用，避免破坏已有调用方。

## 测试与验收

先增加失败的单元测试，覆盖增量目录已可搜索、但未完整时：

- `SHFE.au2612` 本地未命中不会以“合约不存在”拒绝订阅；
- 完整目录后同样的未知合约仍被严格拒绝；
- 已知过期合约继续被拒绝。

Android 代码至少通过 Debug 构建；Python 测试、Electron 测试和核心镜像漂移检查全部
通过。

在 vivo V2528A / Android 16 上安装新 APK 后：

1. 冷启动立即订阅 `SHFE.au2612`，确认首次请求不会被本地目录误拒；
2. 锁屏至少 30 秒，端口转发后的 `/api/v1/status` 保持可响应，行情计数继续变化；
3. 解锁后确认服务仍在、订阅集合与行情页面正常；
4. 记录是否已取得电池优化豁免，以及未豁免时的系统提示路径。

## 非目标

- 不承诺绕过用户主动强制停止应用；
- 不保证所有厂商在用户拒绝系统限制豁免后的永久后台运行；
- 不改变行情服务器对无效合约的最终校验权威性。
