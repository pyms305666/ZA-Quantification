### 2026-09-15 真机测试发现的三个缺陷（新增 P0 修复项，均未改代码）

- [x] **缺陷 C（最严重）：手机端行情 WS 广播管道断裂**——行情持续流入（recv 1976+）但 WS 客户端
  0 条 quote 广播；UI 价格仅靠订阅时内联快照 + REST 轮询。根因三处断点（APK 内源码已核对）：
  ① `services.build_services` 把 `on_quote_change` 挂在 Services 上而非 MobileHub；
  ② 手机 lifespan 只设 `hub.loop` 从未设 `services.loop`（Services 入队条件永假）；
  ③ `MobileHub.on_quote_change→_enqueue→_broadcast_loop` 整链从未注册（死代码）。
  - **完成（2026-09-16，C→F→A→G→B→D→E 全修）**：`services.build_services` 增加可注入
    `on_quote_change` 与 `on_connected` 回调；`MobileHub.__init__` 把自身 `on_quote_change`
    注入 build_services，接管"统计埋点+缓存+广播投递"整条链；广播队列改为 `asyncio.Queue`
    （uvicorn loop 内创建，行情线程经 `call_soon_threadsafe` 投递，即时唤醒，消除旧 0.2s 轮询延迟）。
    桌面版沿用 Services 自带实现，零行为变化。
- [x] **缺陷 A：启动窗口自选订阅丢失且无补偿**——冷启动 90 秒 `subscribed=[]`/价格全 "--"。
  根因：订阅管理器对未连接整批拒绝 + 前端 onopen 只发一次不重试 + 点击默认合约不触发重订。
  - **完成（2026-09-16）**：后端 `SubscriptionManager` 增加 `_pending` 集合——未连接时
    把合约记入 pending 而非整批丢弃；`on_connected` 回调（由 DiffClient 在每次连接建立时
    触发）自动重放 pending。前端 `app.js` WS `subscribed.failed` 收到失败后退避重试
    （1s→2s→4s→5s 封顶，最多 6 次约 20s 窗口），`onopen`/切换合约统一走 `sendSubscribe()`。
    回归测试 `test_pending_replayed_on_connected` + `test_reconnect_replays_existing_subscriptions`。
- [x] **缺陷 B：锁屏后 App 被 vivo 系统冻结，后端停摆**——进程在但 HTTP 12s 无响应。
  - **完成（2026-09-16）**：新增 `BackendService.java` 前台服务（低优先级常驻通知，
    `foregroundServiceType="dataSync"`），后端线程挂在前台服务下，系统对前台服务的
    锁屏冻结阈值远宽松于普通进程。`AndroidManifest.xml` 加 `FOREGROUND_SERVICE` +
    `POST_NOTIFICATIONS` 权限；`MainActivity` 改为 `startService(BackendService)` 并
    在 Android 13+ 运行时申请通知权限。`START_STICKY` 保证被回收后自动重启。
  - 证据与完整分析：`docs/验证记录/2026-09-15/报告-手机端.md`（含 quote 原文、9 张截图、logcat）。
