## 修复批次记录

### 2026-09-16 · 真机缺陷 A–G 全修（C→F→A→G→B→D→E）

**背景**：2026-09-15 真机测试（vivo V2528A · Android 16）与 09-16 早盘补测发现 7 个缺陷，
其中 C/A/F 三个直接导致"手机端 WS 推送不工作"或"断线后行情冻结"。按用户指定顺序
C→F→A→G→B→D→E 逐项修复，**两端核心代码逐字节一致**，55/55 单测通过。

**① 缺陷 C（最严重）· 手机端 WS 广播管道断裂**
- 根因：`build_services` 把 `on_quote_change` 挂在 Services 上（依赖 `services.loop`，
  手机端从未设置），MobileHub 的 `on_quote_change→_enqueue→_broadcast_loop` 整链是死代码——
  WS 客户端一条 quote 都收不到，UI 只能靠 REST 轮询。
- 修复：`services.build_services` 增加可注入 `on_quote_change` 与 `on_connected` 回调；
  `MobileHub.__init__` 把自身 `on_quote_change` 注入 build_services，接管"统计埋点+缓存+广播投递"
  整条链；广播队列改 `asyncio.Queue`（uvicorn loop 内创建，行情线程经
  `call_soon_threadsafe` 投递，即时唤醒，消除旧 0.2s 轮询的 200ms 叠加延迟）。
  桌面版沿用 Services 自带实现，零行为变化。

**② 缺陷 F · 断线重连后行情推送死亡（桌面/手机同病）**
- 根因：`DiffClient._session` 重连后不重放 `subscribe_quote` 和 `set_chart`——服务器断开即
  丢弃本端订阅与图表状态，重连后行情推送计数冻结 2 分钟+。
- 修复：`_session` 在每次 WebSocket 连接建立后（含重连）调用 `_resend_subscribe()`
  重放订阅表 + `_resend_charts()` 重放 set_chart + `_notify_connected()` 触发订阅管理器重放 pending。

**③ 缺陷 A · 启动窗口自选订阅丢失**
- 根因：订阅管理器对未连接整批拒绝 + 前端 onopen 只发一次不重试。
- 修复（后端）：`SubscriptionManager._pending` 集合——未连接时记入 pending 而非整批丢弃；
  `on_connected` 回调（由 DiffClient 在每次连接建立时触发）自动重放 pending。
- 修复（前端）：`app.js` WS `subscribed.failed` 收到失败后退避重试（1s→2s→4s→5s 封顶，
  最多 6 次约 20s 窗口）；`onopen`/切换合约统一走 `sendSubscribe()`。
- 回归测试：`test_pending_replayed_on_connected` + `test_reconnect_replays_existing_subscriptions`。

**④ 缺陷 G · K 线主图 tile memory 超限**
- 根因：手机 WebView tile 内存上限远低于桌面，全量 `setOption` 每次重建所有组件，
  长会话后主图只剩坐标轴（logcat: `tile memory limits exceeded`）。
- 修复：`initCharts` 给 candlestick 加 `progressive: 200` + `progressiveThreshold: 500`
  （ECharts 分块渲染）；`renderKline` 的 `setOption` 传 `{ lazyReplace: true }` 增量更新，
  不重建 grid/yAxis 等静态配置。

**⑤ 缺陷 B · 锁屏冻结**
- 根因：vivo 系统锁屏后冻结普通进程，后端 HTTP 12s 无响应。
- 修复：新增 `BackendService.java` 前台服务（低优先级常驻通知，
  `foregroundServiceType="dataSync"`），后端线程挂在前台服务下，系统对前台服务的
  锁屏冻结阈值远宽松于普通进程。`AndroidManifest.xml` 加 `FOREGROUND_SERVICE` +
  `POST_NOTIFICATIONS` 权限；`MainActivity` 改为 `startService(BackendService)` 并
  在 Android 13+ 运行时申请通知权限。`START_STICKY` 保证被回收后自动重启。

**⑥ 缺陷 D · 合约浏览双重截断**
- 根因：API 硬编码 `limit=200` + 前端 `slice(0,50)`，578 条期货只能看到前 50 条。
- 修复：后端 `mobile_api.py` instruments 路由 `limit=200`→`0`；前端 `renderSearch` 改为
  分批 append（每批 50 条），`resultlist` 滚到底部自动加载下一批。

**⑦ 缺陷 E · 中文关键字搜索失效（桌面/手机同病）**
- 根因：`tq/instruments.py::list()` 候选预过滤只按代码匹配，中文名（如"棕榈"）的合约
  代码里不含该字，被提前丢弃，后置名称匹配永远执行不到。
- 修复：关键字存在时不预过滤——全部进入批量查询，再用名称/代码做后置匹配。
- 回归测试：`test_keyword_matches_name_not_just_code`。

**改动文件清单**（Python 核心两端逐字节同步）：
- 后端核心：`services.py`、`tqdiff/client.py`、`tq/subscriber.py`、`tq/instruments.py`
- 手机端独有：`mobile_api.py`、`static/app.js`

### 2026-09-12 补充 · K 线盘中不更新的根因修复（两端）

- **回归测试**：`tests/test_tqdiff.py::KlineDiffMergeTests`（全字段→部分字段合并后仍完整可解析、

## 0. 一分钟看懂这个项目

**ZA量化** = 一个「国内期货行情网关 + 决策评估系统」，提供**行情读取、合约评估（多/空/观望 + 止损/目标/风险）、专业 K 线界面**。**不涉及下单与自动交易。**

```
┌──────────┐   DIFF 协议   ┌────────────┐   订阅/推送   ┌───────────────┐
│  天勤行情  │ ◄─────────── │  后端数据层  │ ───────────► │  前端 Web UI   │
│  服务器    │              │ tqdiff/    │              │ 行情/K线/决策   │
└──────────┘              └────────────┘              └───────────────┘
```

- **桌面版**：后端跑在本机 `127.0.0.1:8000`（FastAPI + uvicorn），Electron 或浏览器打开前端。
- **手机版**：**Chaquopy 内嵌 Python**，后端也跑在手机本地 `127.0.0.1:8000`，WebView 加载同源前端（**无云服务器**）。这是与 `docs/15-手机版方案.md` 里"云服务器 + PWA"设想**不同的最终落地**（见 §5）。

## 1. Git 分支结构

| 分支 | 路线 | 说明 |
|---|---|---|
| `master` | — | 主分支，稳定版 |
| `route-ab-sync-coroutine` | **A+B 协程路线** | 保留 TqSdk 的渐进修复（TqApi 单事件循环 + 命令队列 + Future 修复） |
| `route-c-diff-direct` | **C 直连路线** | 弃用 TqSdk，直连天勤 DIFF 协议（`tqdiff/`），K线/订阅协程并发，无队列活锁 |
| `mobile-app` | 手机版 | **当前所在分支**，基于 C 路线的 Chaquopy 内嵌 APK |

> `route-ab-sync-coroutine` 与 `route-c-diff-direct` 是上一阶段"开两条平行技术路线验证 K 线阻塞"的产物，
> 都有各自的打包 exe（`dist/ZA量化-AB协程版.exe` / `dist/ZA量化-C直连版.exe`）。
> **当前重心在手机版（`mobile-app` 分支），桌面双路线视为已稳定。**

**注意**：根目录同时存在 `tq/`（适配层）与 `tqdiff/`（DIFF 核心），且同一份代码在 `mobile-app/app/src/main/python/` 下有一份**拷贝**。改桌面版 vs 手机版的入口不同（见 §4、§6）。

## 3. 数据流（核心心智）

### 行情链路
1. 前端 WebSocket 连 `/ws/market`，发 `{action:"subscribe", symbols:[...]}`。
2. 后端 `SubscriptionManager.subscribe` → `DiffClient._subscribe` → 向天勤发 `subscribe_quote`。
3. 天勤推 `diff` → `DiffClient._apply_diff` 合并 → `_dispatch_quote` → `on_quote_change` 回调。
4. 回调写缓存 `QuoteCache` + 投递异步广播队列 → 前端收到 `quote` / `quote_snapshot` 实时渲染。

### K 线链路
- 前端请求 `/api/v1/kline/{symbol}?period=&count=` → 后端 `_get_kline` 向天勤 `set_chart`，缓冲异步到达后返回。

### 决策评估链路
- 前端请求 `/api/v1/decision/{symbol}` → 后端拉多周期 K 线 + 最新行情 → `market.evaluator` 计算多空分数/方向/止损/目标/风险。

### 合约目录链路（当前正在修的重点）
- 天勤的**合约文件** `latest.json`（线上约 334MB，约 23.9 万条合约元数据）**只服务于"搜索合约/名称/乘数"**。
- **订阅行情 / K线 / 盘口 / 决策评估都不依赖它**——行情服务器只认合约代码。
- 目录加载：`DiffClient._load_symbol_file` 后台执行，缓存优先，无缓存则下载（见 §5）。

## 4. 桌面版与手机版的差异（重要）

桌面版与手机版**复用同一套后端逻辑**（`market/`、`tqdiff/`、`services.py`、`mobile_api.py`），
区别只在**入口与环境**：

| 维度 | 桌面版（C 路线） | 手机版 |
|---|---|---|
| 入口 | `api/http.py`（FastAPI） | `mobile_api.py`（starlette，avoid pydantic 原生依赖） |
| 启动 | `main.py` | `backend_main.py` 由 Chaquopy 调用 `run_mobile_server` |
| 端口 | `127.0.0.1:8000` | `127.0.0.1:8000`（App 内） |
| 前端 | `static/` | `mobile-app/app/src/main/python/static/`（独立一份） |
| 数据源 | `tqdiff/`（DIFF） | 同样 `tqdiff/`（DIFF）——但手机版有一份**拷贝** |

> ⚠️ **避坑**：改手机版逻辑要去 `mobile-app/app/src/main/python/` 下改，不要改根目录那份（那是桌面的）。
> 手机版的 `tqdiff/`、`tq/`、`market/`、`services.py`、`config.py`、`mobile_api.py`、`static/`
> **全部在 `mobile-app/app/src/main/python/` 下有拷贝**，需同步修改。

## 5. 手机版架构（与文档的差异，务必先读）

### 5.1 最终落地（实际代码）
- **Chaquopy 内嵌 Python** + **WebView**，后端在**手机本地** `127.0.0.1:8000` 运行。
- **无云服务器**。这与 `docs/15-手机版方案.md` 里"手机 App 连云服务器后端（PWA/Capacitor）"的设想**不同**。
- 之所以改：用户要求"独立、不连电脑/服务器"，Chaquopy 内嵌正好满足。

### 5.2 手机版模块划分（`mobile-app/app/src/main/`）
```
python/                          # Chaquopy 打包的 Python 后端
├── backend_main.py              #   Android 入口：模块导入即启动一次后端（线程内）
├── config.py                    #   配置 + 凭据（写 App 私有目录 za.filesdir）
├── mobile_api.py                #   starlette 接口层 + run_mobile_server
├── services.py                  #   build_services（复用）
├── market/                      #   决策评估（复用）
├── tq/                          #   适配层（复用）
├── tqdiff/                      #   DIFF 核心（复用；含新增 symbol_index.py）
│   ├── auth.py                  #     登录/名称服务/合约文件下载（gzip+ijson）
│   ├── client.py                #     DiffClient
│   └── symbol_index.py          #     【新增】合约精简索引
└── static/                      #   手机版前端（6 屏：行情/K线/盘口/决策/我的/登录）
java/com/zaquant/mobile/MainActivity.java   # WebView + startService(BackendService) + waitAndLoad
java/com/zaquant/mobile/BackendService.java # 【新增】前台服务保活（缺陷 B），onCreate 内 Python.start + backend_main
build.gradle                     #   AGP 8.2.2 + Chaquopy 16.1 + pip 依赖
```

### 5.3 手机版关键机制
- `MainActivity.java`：Android 13+ 申请 `POST_NOTIFICATIONS` 权限后
  `startService(new Intent(this, BackendService.class))`（缺陷 B 前台服务保活）。
- `BackendService.java`：前台服务（`foregroundServiceType="dataSync"`，低优先级常驻通知），
  `onCreate` 内 `Python.start(new AndroidPlatform(this))` + `System.setProperty("za.filesdir", ...)`
  + 调 `backend_main.start()`；`START_STICKY` 保证被回收后自动重启。锁屏冻结阈值远宽松于普通进程。
- `backend_main.files_dir()`：读 `za.filesdir` 或 `TQ_MOBILE_FILES_DIR`，判定 App 私有可写目录。
- WebView 轮询 `http://127.0.0.1:8000/api/v1/status` 直到 200 再 `loadUrl`。

## 6. 合约目录下载 —— 当前正在修的问题（重点）

### 6.1 现象（用户真机反馈）
1. 打开 App 显示"正在下载合约目录"，**等了 5~6 分钟甚至更久**仍不显示。
2. **下载到 4MB 左右又归零**，从头重下。
3. 自选价格 `--`、搜索不可用（虽已标记"行情已可用"）。

### 6.2 根因链（已查明）
| 根因 | 说明 |
|---|---|
| **服务器限速** | 天勤对 `latest.json` 下载限速在 **约 0.5 MB/s**。实测电脑端下载同一文件 120 秒也只到 15MB，`catalog_ready=False`。**与手机网络无关，对谁都慢。** |
| **文件巨大** | 明文 JSON **334MB**（`Content-Length: 350174892`）。 |
| **旧代码 json.loads OOM** | 之前 `download_symbol_file` 下载后 `json.loads(tmp.read_text())` 把 334MB 一次读入 → 手机内存爆 → 进程被杀 → **"下载到一半又从 0 重下"**。 |
| **gzip 未利用** | 服务器支持 gzip，压缩后仅 **8.3MB（30 倍压缩）**，但旧代码没显式请求。 |
| **`raw.stream(chunk_size=)` 参数错误** | urllib3 的 `stream()` 参数是 **`amt=`** 不是 `chunk_size`；用错会抛 `TypeError` → 被当"下载中"卡住（已修复为 `amt=`）。 |
| **断点续传缺失** | 下载中途失败（弱网/超时）会 `tmp.unlink()` 删掉临时文件，下次**从 0 重新下载**——这就是"4MB 归零"。 |

### 6.3 已做的修复（`mobile-app` 分支未提交改动）
- **gzip 下载**：`auth.py` 请求加 `Accept-Encoding: gzip`，`response.raw.stream(amt=256*1024, decode_content=False)` 拿压缩字节直接落盘 `.gz`，只写 ~8.3MB。
- **ijson 流式解析**：新增 `symbol_index.py`，用 `ijson.kvitems` 边解压边逐条解析成**精简 record**（不一次性加载全量）。
- **pickle 索引持久化**：解析结果存 `symbol_index.pkl`（约 25.6MB，238877 条），**二次打开 0.28 秒秒开**。
- **增量就绪**：`_on_index_progress` 解析到 1000 条即 `_file_loaded.set()`，搜索尽早可用。
- **前端门控**：目录未就绪时 `loadInstruments` 不再反复请求/报错，只提示"目录下载中"。
- **前端自选价格缓存**：`state.quotes` 缓存 + `renderWatchlist` 重建后回填价格（解决切屏价格变 `--`）。
- **订阅不等待目录**：`_subscribe` 改用 `_file_loaded.is_set()` 直接判断，不 `_wait_file`，行情即时可用。

### 6.4 仍未解决（接下来的坑）
- **根因仍是"天勤服务器下载限速 0.5MB/s"**，即便 gzip 后仅 8.3MB，网络层也要 ~17 秒（弱网更久）。
- **没有断点续传**：下载失败仍会把 `.tmp` 删除，从 0 重下。**这是"4MB 归零"的遗留根因**。
- **`load_cached_symbol_file` 的 TTL**：手机版已改成 `SYMBOL_CACHE_TTL = 7*24*3600`（原本桌面版是 24h）。
- **桌面版 `tqdiff/auth.py` 的 TTL 仍是 24h**，且桌面版 `download_symbol_file` **未**同步 gzip/ijson 改造（桌面那份还是旧 256MB 全量 + `json.loads`）。
