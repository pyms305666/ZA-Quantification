## 失败与待修项

### B：锁屏后本机后端仍会冻结（FAIL）

锁屏前 `quote_recv_total=508`。屏幕处于 `mWakefulness=Asleep` 时，ADB 转发到
手机 `127.0.0.1:8000` 的状态接口连续两次在 15 秒超时；此时 Android 系统仍显示
BackendService 为前台服务。手动解锁并回到 App 后，状态接口在 208ms 内恢复响应。

结论：`dataSync` 前台服务及 Android 14 类型专用权限已正确生效，但在该 vivo Android 16
设备上仍不足以保证 Python/uvicorn 后端在锁屏时继续响应。发布前必须继续定位进程冻结、
厂商后台限制或保活策略。

### A：目录增量解析早期会误拒绝部分自选合约（PARTIAL）

冷启动连接成功、WebView 已连接时，初始订阅只包含 rb2610 / p2610 / bb2611；对 au2612 的
订阅接口返回“合约不存在”，但同一手机的报价接口随后能返回完整 au2612 行情。目录继续解析后，
最终订阅表包含四个自选合约。

推断根因：目录在增量就绪阶段已把 `catalog_ready` 置为真，但尚未解析到的合约被
`InstrumentManager` 当作“目录完整但查无此合约”严格拒绝；前端后续重试恰好在目录包含该条目后
成功。应区分“目录可搜索”与“目录完整”，在解析未完成时保持订阅降级放行。

### 观察项

- 四个订阅最终都保留，但 `quote_count=3`，页面中的 bb2611 仍无最新价；该合约可能在当前时段
  无有效报价，需换活跃合约或在后续交易时段复测，不能据此判为推送故障。
- `logcat -b crash` 出现的 `UiAutomation` Bad file descriptor 属于测试工具进程 PID，不是
  `com.zaquant.mobile` 进程；本轮未观察到应用进程的 FATAL 或 Python Traceback。

## 结论

候选包的行情接收、WS 广播、断网重连、目录搜索、K 线和决策链路可用；锁屏保活未闭环，且
目录增量完成前的订阅判定存在竞态。该 APK 不应标记为正式通过验收或作为 release 发布物。
