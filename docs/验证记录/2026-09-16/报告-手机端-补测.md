## ⚠️ 新发现缺陷

### 缺陷 F：断线重连后行情推送死亡——重连不重新提交订阅（P0）
- 流程：09:32:57 开飞行模式（断网中 `connected=False`，recv=26）→ 09:33:27 恢复
  → t+20s `connected=True` → **但 recv 冻结在 26 持续 2 分钟以上**，`last_quote` 年龄 206s+。
- 交叉验证：缓存报价 last=3069（断网前旧值），而 `get_kline` 最新 1 分 K close=3068（当根、新鲜）。
  → **拉取（K 线）恢复、推送（行情）死亡**：天勤 DIFF 断线后服务端订阅丢失，客户端重连后
  没有为已订阅合约重新提交 subscribe，行情推送静默消失。
- 影响：断网/后台冻结/服务端重启后，UI 报价永久冻结（叠加缺陷 C，前端无任何自愈手段）；
  这正是"K 线在动、价格不动"现象的另一半根因（K 线 20s 轮询是拉取所以活着）。
- 对应待办："处理 WebSocket 断开、重连、重复订阅和服务端重启后的订阅恢复"——桌面/手机同一实现，两端同病。
- 修复方向：client 重连成功后按 `SubscriptionManager._subscribed` 重放全部订阅。

### 缺陷 G：K 线主图 WebView 渲染失败（tile memory 超限）
- 现象：早盘会话中 K 线主图只剩坐标轴，蜡烛/MA 不画（MACD 部分画出）；logcat 每 20s 一次
  `E chromium: tile memory limits exceeded, some content may not draw`——与 loadKline 轮询重绘节奏一致。
- 说明：09-15 下午同机 K 线渲染正常，属状态相关（长会话/重复 setOption 后内存劣化）；
  REST 数据本身有效（curl 正常），纯渲染层问题。
- 修复方向：控制 setOption 频率/增量更新（对应待办"避免每条消息全量 setOption"）、
  ECharts `progressive`/降采样、必要时降级 canvas 分辨率。
