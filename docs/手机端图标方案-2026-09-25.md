# 手机端应用图标实施方案（2026-09-25）

> 实施状态：2026-09-25 已按本方案加入图标并完成模拟器/真机检查。实施与验收细节见
> [真机验收记录](真机验收与图标实施-2026-09-25.md)。以下保留原设计方案，供后续调整使用。

## 现状

- 仓库已有桌面图标 `assets/icon.png`（256 × 256）、`assets/icon.ico` 和网页图标 `assets/favicon.png`。
- `assets/icon.png` 的视觉元素为深色圆角底、蓝色方块和金色菱形。
- Android `mobile-app/app/src/main/res/` 目前只有 `values/`；Manifest 的 `<application>` 没有 `android:icon`。新构建 APK 的 `aapt dump badging` 显示空图标，lint 报 `MissingApplicationIcon`。

## 资源制作

1. 以现有 `assets/icon.png` 为视觉基准，制作一份可编辑的矢量母版或至少 1024 × 1024 的无损母版。保留蓝色方块与金色菱形的比例和颜色；将深色底单独作为背景层，前景导出透明 PNG。现有 256 × 256 成品已包含圆角背景，直接作为自适应前景会被系统再次裁切，容易出现双重边框。
2. 在 Android Studio 的 Image Asset Studio 中生成 **Adaptive and Legacy** Launcher Icons：前景使用透明图形，背景使用与桌面图标一致的深色；确认圆形、圆角方形及其他系统遮罩下主体均位于安全区域。建议使用 `ic_launcher` 与 `ic_launcher_round` 命名。
3. 生成的资源放在 `mobile-app/app/src/main/res/mipmap-*` 和 `mipmap-anydpi-v26/`。普通图标覆盖 mdpi、hdpi、xhdpi、xxhdpi、xxxhdpi；Android 8+ 使用自适应图标 XML。按需提供单色层以适配 Android 13+ 主题图标。
4. 前台服务通知使用单独的单色小图标（建议 `drawable/ic_notification`），不要把彩色 Launcher 图标直接用于通知栏。当前服务用的是系统下载图标，若希望通知也体现品牌，可在同一轮资源工作中替换。

## 接入位置

在 `mobile-app/app/src/main/AndroidManifest.xml` 的 `<application>` 中引用 `@mipmap/ic_launcher`，并在确实生成圆形资源时引用 `@mipmap/ic_launcher_round`。若制作通知小图标，再更新 `BackendService.java` 的通知 `setSmallIcon` 引用。图标工作不需要改行情、评估或订阅逻辑，也不需要改包名和版本号。

## 验收标准

1. `assembleDebug`、`assembleRelease` 均成功；`lintDebug` 不再出现 `MissingApplicationIcon`。当前 lint 另有 API 兼容错误，需单独解决后才能取得完整通过结果。
2. `aapt dump badging app-release.apk` 中 `application: ... icon=` 非空；`apksigner verify --print-certs` 通过且证书与现有发布证书一致。
3. 在 API 24/25、API 26+ 和 API 33+ 设备或模拟器上检查桌面、应用抽屉、系统设置及最近任务中的图标；查看圆形/方形裁切、透明边缘和浅色/深色背景下的辨识度。若提供单色层，还要检查主题图标。
4. 若更换通知小图标，启动前台服务后检查状态栏和通知详情，确保图标清晰且不是系统下载标识。
5. 将最终母版、导出规格和 APK 签名校验结果记录在发布资料中，避免后续版本出现图标或签名回退。

## 本次实施选择

现有标志由简单几何形状构成。本次用 `assets/icon-android.svg` 保存可编辑母版，
并使用 Android `VectorDrawable` 实现 API 24/25 图标与通知图标；Android 8+ 使用
`AdaptiveIconDrawable`，同时提供 Android 13+ 单色层。矢量图标可覆盖各屏幕密度，
因此无需额外生成多套位图。配色取自现有桌面图标：深色 `#0E1116`、蓝色
`#55B7D9`、金色 `#E4AD4A`。真机应用信息页与 API 34 模拟器应用抽屉均已检查图标。
