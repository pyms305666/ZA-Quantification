# 手机版问题 · 第二次修复方案（待审批）

> 对应真机反馈：
> 1. "合约目录下载了很久还没显示"
> 2. "自选价格要加载很久才有，转到别的界面再回来又没了"
>
> 本方案先给出根因分析，再给出要做的改动清单。**未审批前不修改代码。**

---

## 一、关键背景（联网核实）

TqSdk DIFF 协议的"合约文件"（`latest.json`，约 256MB，约 23.9 万条合约的完整元数据）
是一个 **纯静态的元数据仓库**，它只服务于"合约搜索 / 名称 / 价格乘数 / 到期日"这类信息。

**订阅行情（`subscribe_quote`）、K线（`set_chart`）、五档盘口、决策评估，都不依赖这个文件。**
行情服务器只认合约代码（如 `SHFE.rb2610`），不认合约文件。

也就是说：**当前为了一个"搜索"功能，让整个 App 的门户状态（`catalog_ready`）
卡在"必须下完 256MB"，是本末倒置。** 这直接造成你看到的"目录下不完 → 价格迟迟不进 → 搜索不可用"连环问题。

---

## 二、现状问题定位（代码级）

| 现象 | 根因（在哪个文件） |
|---|---|
| 目录下载很久没显示 | `tqdiff/client.py::_load_symbol_file` 只有缓存命中才秒就绪；没缓存就下载 256MB，手机上极慢；下载失败会 **无限 10s 重试**（`_status` 一直"下载中"） |
| 下载失败影响所有功能 | `SubscriptionManager.subscribe` 之前会先查目录，目录没就绪时报"合约不存在"；我已改为"目录未就绪直接订阅"，但 `_wait_file(5.0)` 仍让每次订阅**多等 5 秒**才走兜底 |
| 切屏后自选价格变 `--` | `static/app.js::showScreen("quotes")` → `renderWatchlist()` 用 `innerHTML=""` **清空重建**所有自选行（价格初始化为 `--`）。重建后的 DOM 只能等 WebSocket 再次推送才有值；行情不变或 WS 重连中期间就一直是 `--` |
| 价格"要加载很久才有" | 订阅后要等 `_wait_file` + 首笔行情推送；若依赖目录就绪，等待更久 |

---

## 三、修复方案

### 改动 1：合约目录改为"后台静默下载，不与核心功能挂钩"【核心】

**目标**：让"订阅/行情/K线/决策"完全不依赖合约目录就绪；目录只影响"搜索"。
目录下载时**不影响任何现有功能**，且**下载进度在后台持续显示**（你已经看到的黄色提示条保留）。

- `tqdiff/client.py`：
  - `_load_symbol_file` 的下载循环不再因为"某次失败"而长期卡住状态；失败就继续后台重试，但**绝不阻塞 `catalog_ready` 供其它接口判断**（目录未就绪 = 只是"搜索暂不可用"，不是"行情不可用"）。
  - `_subscribe` 里 **去掉 `_wait_file(5.0)` 的等待**——目录有没有都直接订阅（用 `_candidates` 规范化代码），显著缩短"要加载很久才有"。
  - `_get_kline` / `_get_instrument` 等强依赖目录的操作**保持等待**，但只影响搜索和精度，不影响行情。

### 改动 2：前端"切屏价格不丢失"【解决现象二】

**目标**：切屏后自选价格立刻恢复，不依赖下一笔行情推送。

- `static/app.js`：
  - 维护一个 **`state.quotes` 缓存**（`{symbol: quote}`），WebSocket 每收到一条行情就写入它。
  - `renderWatchlist()` 重建自选行后，**立刻从 `state.quotes` 里把每行当前价格回填**（调 `updateWatchPrice`），而不是留给下一笔推送。
  - `switchSymbol()` 时也把该合约写入 `state.quotes`。
  - 这样"切到别的界面再回来"，价格是**从内存缓存立刻恢复**的，不再出现 `--`。

### 改动 3：缩短"加载很久才有"的等待

- 订阅后**立即主动重放**当前快照（`_dispatch_quote` 快照逻辑已存在，确保订阅成功即给前端一次价格）。
- `updateWatchPrice` 在收到 `quote_snapshot`（订阅成功回放）时也更新，不依赖实时推送。

### 改动 4（可选，提升首次体验）：目录下载体验优化

- 将合约文件下载改为**显示具体进度**（"已下载 xx MB / 总 256 MB"），并提示"可在下载完成前先看行情，搜索稍后可用"。
- 首次下载完成后以 **pickle 缓存**（上一轮已改），下次启动快速读取。

---

## 四、验收标准

1. **打开 App → 连接成功即看到自选价格**（哪怕目录还在下载）。不再"要等很久才有"。
2. **切到 K线/我的/决策，再切回行情主页，自选价格立刻显示**，不出现 `--`。
3. **目录下载期间**，行情、K线、盘口、决策全部可用；只有"搜索"提示"目录下载中"。
4. **目录下载完成后**，搜索可用、黄色提示条消失。
5. 首次下载进度可见（xx MB），二次打开从缓存秒就绪。

---

## 五、影响范围

- 改动集中在手机版后端 `tqdiff/client.py`、`tqdiff/auth.py` 和前端 `static/app.js`。
- **不影响桌面版**（桌面版用的是独立的 `tq/`、`diff/`，无此手机特有问题）。
- 改动后需重新打出 APK。
