# 练习02 参考答案（读 main.py 回答问题）

> 理解题没有唯一标准答案，下面是**要点**。你写的大意相同即算通过。

## 问题 1：程序"停"在哪一行？为什么不会执行到文件末尾？

**答**：停在 `uvicorn.run(app, host=..., port=...)` 这一行。

`uvicorn.run` 的意思是"开始提供网站服务，一直服务下去"——它内部是一个**永不主动结束的循环**：
监听 8000 端口 → 等请求 → 处理请求 → 继续等……直到你按 Ctrl+C 或关闭窗口。

所以执行到这一行后，`main()` 函数**回不来了**，`main.py` 后面自然也没了"然后"。
这就是为什么叫"启动服务"而不是"运行一次"：它不是做一件事就结束，而是进入一种持续工作的状态。

## 问题 2：`python main.py --debug-stack` 的区别是哪行代码造成的？

**答**：区别来自这一行：

```python
if "--debug-stack" in sys.argv:
    faulthandler.dump_traceback_later(30, repeat=True, file=sys.stderr)
```

- `sys.argv` 是命令行参数列表：`python main.py --debug-stack` 时它等于 `["main.py", "--debug-stack"]`；
- 带了这个参数 → 每 30 秒自动把**所有线程当前停在哪一行**打印到 stderr（诊断"程序卡死"用）；
- 不带 → 诊断器不开启，程序安静运行。

**用法记忆**：程序"假死/卡住"时，加 `--debug-stack` 重启，看日志里的线程快照。

## 问题 3：删掉 `if __name__ == "__main__":` 会怎样？

**答**：`main()` 会在**被 import 的瞬间就执行**。

后果演示：任何一个文件写 `import main`（哪怕只是想借用 main.py 里的某个函数），
导入的那一刻就会直接启动服务器——卡在 `uvicorn.run` 里不返回，
那个文件后面的代码全都无法执行，正在运行的 8000 服务还会因为端口被占而报错。

这个判断的作用：**区分"直接运行"和"被别人导入"两种使用方式**——
直接运行才启动服务；被导入时只提供函数，什么也不做。
这是 Python 的经典惯用法，几乎所有脚本入口都这么写。

## 问题 4：`faulthandler.dump_traceback_later(30, repeat=True)` 是干什么用的？

**答**：设一个重复闹钟：每 30 秒把程序里**所有线程当前执行到哪一行**打印到 stderr。

使用场景：程序**卡死/假死**的时候——你不知道它停在哪、也不知道哪个线程出的问题。
有了这个"定时现场快照"，日志里会周期性出现每个线程的调用栈，
一眼看出"哪个线程卡在哪个文件的哪一行"。

本项目真实用过：排查 v1.1.1 的"首屏活锁"事故时，就是靠这类线程栈快照确认
"事件循环线程卡在目录查询、其他线程卡在等待"。

## 问题 5（动手）：两个服务并存

**答**：把端口改成 8001 后，8000 和 8001 是**两个完全独立的服务**：
各自有自己的行情连接、自己的缓存，互不冲突——因为它们只听各自的端口。

两个注意点：
1. 两个服务会建立**两条天勤连接**——免费账户连接数有限，不建议长期双开（实验完关掉一个）；
2. 浏览器同时开 `127.0.0.1:8000` 和 `127.0.0.1:8001` 可以对比数据——
   这也是开发时"新版/旧版同时运行对比"的常用技巧。
