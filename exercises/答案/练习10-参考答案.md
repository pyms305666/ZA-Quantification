# 练习10 参考答案（前端加"结算价"显示）

> 三件套各改一处。改完 Ctrl+F5 强刷验证。

## 第 1 处：HTML（static/index.html）——摆骨架

找到"昨结"那一格：
```html
<div><label>昨结</label><span id="m-preclose">--</span></div>
```
在它后面照葫芦画瓢加一格（只改 label 文字和 id）：
```html
<div><label>结算</label><span id="m-settlement">--</span></div>
```
要点：`id` 是 JS 的寻址锚点，必须全局唯一；`--` 是数据没来时的占位。

## 第 2 处：JS（static/app.js）——填数据

找到 `renderQuoteBar()` 里这一行：
```js
set("m-preclose", q.pre_close);
```
在它后面加：
```js
if (q.settlement != null) set("m-settlement", q.settlement);
```
要点解释：
- `set(...)` 是 app.js 里现成的小工具（填数字 + 按相对昨收的涨跌自动染色）；
- `q.settlement != null` 才填——**后端没给的字段显示 "--"**，不填假数据；
- 为什么用 if 而不直接 set？因为 `set` 收到 null 会显示 "--" 但也可能染色异常——
  缺数据时干脆不碰这个格子。

## 第 3 处：CSS（可选，不写也行）

不需要新样式——`m-settlement` 和其他格子共用 `.qb-metrics span` 的样式。
**这就是 CSS 变量/公共类的好处**：新元素自动获得外观。

## 第 4 处：验证与提交

- Ctrl+F5 强刷（app.js 带 `?v=` 参数的话正常刷新即可）；
- 交易时段显示数字；非交易时段可能显示 "--"（数据源没给结算价，正常）；
- 提交：
```powershell
git add -A ; git commit -m "feat: 报价头新增结算价显示（练习10）"
```

## 思考题参考答案（?v= 缓存爆破）

浏览器为了速度会把 CSS/JS 文件**缓存到本地**，下次访问同一地址就直接用缓存——
你改了文件，浏览器可能还在用旧的（这就是"改了代码页面没变化"的头号原因）。
`?v=1.2.2-c` 是查询参数，改版本号 = 换了一个**新地址** = 缓存失效强制重新下载。
所以本项目每次改前端代码都会同步改 `?v=` 的版本号。
