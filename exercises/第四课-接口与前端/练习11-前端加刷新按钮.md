# 练习11：前端加"刷新"按钮（操作题）

> 对应 docs/13 §4.5。练"给元素绑事件 + 手动触发数据加载"。

## 步骤

1. **HTML**：在 `static/index.html` 的工具栏里（"账户"按钮旁边）加：
   ```html
   <button id="refresh-btn" class="account-btn">刷新</button>
   ```
2. **JS**：在 `static/app.js` 找到其他按钮绑定的位置（搜 `addEventListener`），
   在附近加：
   ```js
   $("refresh-btn").addEventListener("click", () => {
     loadKline(); loadDecision(); loadInstruments(); loadStatus();
     console.log("手动刷新完成");
   });
   ```
3. **验证**：F12 打开控制台（看 console.log），点"刷新"按钮——
   确认四个加载函数都被触发（控制台无报错、数据有更新）；
4. **进阶**：给按钮加个"转圈"效果——点击时按钮文字变"刷新中..."，2 秒后变回"刷新"：
   ```js
   const btn = $("refresh-btn");
   btn.textContent = "刷新中...";
   setTimeout(() => { btn.textContent = "刷新"; }, 2000);
   ```
5. git 提交：`git commit -m "feat: 工具栏新增手动刷新按钮（练习11）"`

## 检查点

- [ ] 点按钮时四个数据源都重新加载
- [ ] 控制台没有报错
- [ ] 进阶的"刷新中..."效果也做了

## 思考题

这个按钮和页面里每 6s/15s 的自动轮询功能上重复了——为什么实际软件里还是常常
两个都做？（提示：用户"感觉卡了"的时候，一个能点的按钮比解释轮询机制更能安抚。）
